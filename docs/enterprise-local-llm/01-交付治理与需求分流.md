# 企业本地大模型部署：立项、分流与交付治理

> **适用范围**：本章适用于企业本地大模型部署项目的售前评估、PoC、生产交付、移交维保与退场治理，供客户业务、IT、安全、数据/合规团队及服务方联合执行。
>
> **非法律意见**：本章提供的是项目治理与技术控制建议，不构成法律、监管或审计意见。数据定级、跨境、行业监管、模型与软件许可证等结论，应由客户法务、合规、数据 Owner 及相关主管部门或专业机构最终确认。
>
> 所有性能、效果与容量承诺必须以客户数据集、目标硬件和约定压测方法的实测结果为准。

## 1. 服务边界

### 1.1 服务目录与责任边界

| 服务域 | 服务方负责 | 客户负责 | 默认不包含/需另行立项 | 边界证据 |
|---|---|---|---|---|
| 售前评估 | 访谈、现状盘点、路线建议、风险识别、粗估 BOM | 提供真实需求、预算、约束及决策人 | 免费深度 PoC、正式安全测评、法律意见 | 需求确认单、风险清单 |
| PoC | 安装试验环境、部署候选模型、执行约定测试、形成结论 | 提供脱敏样本、测试账号、算力和业务专家 | 生产 SLA、全量数据治理、无限轮调优 | PoC 计划与报告 |
| 方案设计 | 架构、容量、网络/存储/软件栈、实施与回退方案 | 审批架构、确认机房条件、采购与许可证 | 替客户作采购决策或承诺厂商交期 | 设计说明书、BOM、兼容矩阵 |
| 基础设施准备 | 给出检查表、协助验机和兼容性核验 | 采购、收货、上架、供电、散热、网络、安全域开通 | 机房施工、综合布线、硬件维修 | 机房就绪签字单 |
| 部署实施 | 按批准版本安装平台、模型及配套组件，记录配置 | 提供变更窗口、管理员配合、访问授权 | 未审批的软件、模型权重或破解许可证 | 部署记录、制品清单、配置基线 |
| 数据/RAG | 设计接入、切分、索引、权限过滤与评测 | 确认数据权属、分级、授权、质量和保留期限 | 替客户认定数据合法性；无边界抓取数据 | 数据清单、处理记录、评测报告 |
| 微调/训练 | 可行性评估、训练流程、实验追踪与模型注册 | 提供合规数据、标注规则、效果验收专家 | 默认不含全量训练、长期标注运营 | 数据卡、实验报告、模型卡 |
| 安全合规 | 落实已确认的技术控制，提供配置与审计证据 | 法务/合规作最终判断并接受剩余风险 | 法律意见、等保/密评/行业认证代办 | 合规确认单、控制证据包 |
| 验收上线 | 按基线测试、修复约定缺陷、培训和移交 | 组织 UAT、签字、批准上线 | 新增范围或未定义指标的免费优化 | 验收报告、上线审批、移交清单 |
| 维保运维 | 按合同监控、巡检、故障响应、补丁建议 | 一线报障、账号审批、业务运营、变更批准 | 未约定的 7×24、驻场、容量扩容、模型效果运营 | SLA 月报、工单、巡检报告 |
| 退场 | 导出约定配置与文档、撤销服务账号、协助擦除验证 | 确认数据保留策略、接收资产并签署退场 | 数据长期托管、硬件处置 | 退场单、擦除/销毁证明 |

### 1.2 必须书面确认的假设

1. **效果不兜底**：不承诺模型对所有问题正确；业务方必须定义可测任务、基线和容错方式。
2. **容量以实测校准**：参数量或 GPU 型号不能替代并发、上下文、输出长度与批处理压测。
3. **合规由客户定责**：数据权属、跨境、行业监管、模型许可证和内容责任由客户法务/合规最终批准。
4. **客户控制生产权限**：服务方仅使用实名、限时、最小权限账号；禁止共享管理员账号。
5. **变更必须受控**：硬件、驱动、固件、模型、镜像、拓扑、接口或验收口径变化均进入变更流程。
6. **第三方依赖不代担保**：硬件交付、商业许可证、运营商链路和开源组件缺陷按供应商边界处理。

### 1.3 项目门禁

| 门禁 | 放行必备项 | 审批人 | 未通过处理 |
|---|---|---|---|
| G0 商机进入评估 | 业务目标、预算级别、决策链、数据敏感级别初判 | 客户业务负责人、服务方售前负责人 | 补充访谈或关闭商机 |
| G1 PoC 启动 | PoC 范围、样本、指标、资源、周期、退出标准 | 双方项目负责人 | 不进入安装 |
| G2 生产设计冻结 | 架构/BOM、兼容矩阵、SLA、合规结论、变更基线 | 架构、安全、合规、项目委员会 | 返回方案设计 |
| G3 部署开工 | 机房、网络、账号、制品、备份和回退方案就绪 | 客户 IT 负责人 | 延期开工，不带病实施 |
| G4 上线 | 验收通过、遗留风险获签、监控和值班就绪 | 业务 Owner、IT、安全 | 回退或限流灰度 |
| G5 移交/维保 | 文档、培训、资产台账、SLA 联系树完成 | 双方项目负责人 | 延迟移交 |
| G6 退场 | 数据处置、账号撤销、资产归还、证据归档 | 客户数据 Owner、IT、安全 | 暂停关闭，补齐证据 |

## 2. 端到端阶段地图

### 2.1 总览

| 阶段 | 关键决策 | 里程碑 | 建议周期（不含采购等待） |
|---|---|---|---|
| P0 商机筛选与边界确认 | 是否值得继续评估 | G0 | 1—3 个工作日 |
| P1 需求发现与合规分流 | 可否做、在哪里做、哪些数据可用 | 需求/合规基线 | 3—10 个工作日 |
| P2 PoC 设计与验证 | 技术路线和价值假设是否成立 | G1、PoC 结论 | 1—4 周 |
| P3 生产方案与容量设计 | 拓扑、BOM、SLA 和预算是否平衡 | G2 | 1—3 周 |
| P4 采购与机房准备 | 基础设施是否满足实施条件 | G3 | 依采购交期 |
| P5 安装部署与基线固化 | 平台能否重复安装并稳定启动 | 部署完成 | 3 天—3 周 |
| P6 应用联调与安全加固 | 端到端功能、权限和审计是否闭环 | 联调完成 | 1—4 周 |
| P7 验收、灰度与上线 | 是否达到签约标准且风险可控 | G4 | 1—3 周 |
| P8 移交与持续维保 | 运维组织能否独立接管 | G5 | 持续 |
| P9 退场与数据处置 | 资产和数据是否闭环退出 | G6 | 2—10 个工作日 |

### 2.2 各阶段执行卡

#### P0 商机筛选与边界确认

| 要素 | 内容 |
|---|---|
| 前置条件 | 有明确客户主体、业务联系人和初步应用设想 |
| 输入 | 商机信息、预期时间、预算级别、现有 IT 环境概况 |
| 步骤 | ①确认业务问题及“不做的后果”；②识别决策人/预算人/数据 Owner；③讲明服务边界与效果非保证；④筛查致命约束；⑤决定进入访谈、补充信息或停止 |
| 产物 | 商机评估表、干系人图、初版风险清单、服务边界确认 |
| 验收 | 业务 Owner 与客户项目负责人明确；至少一个可量化目标；无未披露的致命限制 |
| 回退 | 信息不足则退回客户补充；目标与预算明显不匹配则关闭或缩为咨询 |
| 责任角色 | A：服务方售前负责人；R：售前架构师；C：客户业务 Owner、IT、采购；I：双方管理层 |

#### P1 需求发现与合规分流

| 要素 | 内容 |
|---|---|
| 前置条件 | G0 放行；客户业务、IT、安全、数据、法务/合规代表可参加 |
| 输入 | 访谈问卷、数据样本说明、网络与机房现状、行业要求 |
| 步骤 | ①按问卷访谈并记录“当前值/目标值/证据”；②完成数据分级；③执行联网、地域、许可证、信创与行业监管分流；④形成候选场景评分；⑤登记假设、例外和待客户裁定项 |
| 产物 | 已签需求表、数据分类清单、合规分流记录、场景优先级、待决策清单 |
| 验收 | 所有强制问题有答案或责任人/截止日；敏感数据均有 Owner；部署边界与联网模式明确 |
| 回退 | 合规结论不明时仅用合成/脱敏数据评估；无法合法使用数据则暂停对应场景 |
| 责任角色 | A：客户项目负责人；R：业务分析师、解决方案架构师；C：客户法务/合规、安全、数据 Owner、IT；I：采购、管理层 |

#### P2 PoC 设计与验证

| 要素 | 内容 |
|---|---|
| 前置条件 | 需求基线明确；PoC 数据获授权；资源、周期及退出标准获批 |
| 输入 | 优先场景、脱敏/授权样本、质量基线、候选模型和硬件 |
| 步骤 | ①把目标转为测试用例；②冻结模型/提示词/RAG/参数版本；③先做最小闭环，再测效果和性能；④记录失败样本、资源利用率和成本；⑤与现状基线对比；⑥给出继续、调整或停止建议 |
| 产物 | PoC 计划、测试集、运行记录、效果/性能报告、生产差距清单 |
| 验收 | 达到预先约定阈值；结果可复现；关键失败类型和生产差距已披露 |
| 回退 | 先回退参数/量化版本，再回退模型或 RAG 路线；达到试验轮次/预算上限即停止 |
| 责任角色 | A：客户业务 Owner；R：算法/平台工程师；C：业务专家、架构师、安全；I：项目委员会 |

#### P3 生产方案与容量设计

| 要素 | 内容 |
|---|---|
| 前置条件 | PoC 有结论或客户书面接受跳过 PoC 的风险；SLA 和增长假设明确 |
| 输入 | PoC 数据、峰值并发、上下文/输出长度、可用性、预算、机房约束 |
| 步骤 | ①按峰值负载估算并实测校准；②比较单机、多副本、多机并行；③设计故障域、存储、网络和备份；④冻结版本兼容矩阵；⑤评审 BOM、SLA、安全和扩容触发线；⑥形成实施/回退方案 |
| 产物 | HLD/LLD、BOM、容量模型、兼容矩阵、实施计划、风险登记册 |
| 验收 | 目标负载下有约定余量；无单点或单点获风险签字；预算及机房条件可承载 |
| 回退 | 降低 SLA/上下文/并发，分阶段建设，或返回 PoC 更换路线；禁止以删除冗余但不披露风险的方式压价 |
| 责任角色 | A：联合项目委员会；R：解决方案架构师；C：平台、网络、存储、安全、设施、采购、财务；I：业务用户 |

#### P4 采购与机房准备

| 要素 | 内容 |
|---|---|
| 前置条件 | G2 设计冻结；采购清单和责任边界审批完成 |
| 输入 | BOM、机柜图、功耗/散热、端口矩阵、IP/DNS/NTP、交付计划 |
| 步骤 | ①核对料号与许可证；②到货验机和资产登记；③核验机架承重、供电、UPS、散热；④配置网络区、带外管理、存储；⑤做固件/硬件兼容检查和烧机；⑥签署就绪单 |
| 产物 | 资产台账、验机/烧机报告、网络与机房就绪单、故障件清单 |
| 验收 | 设备型号数量一致；烧机无阻断错误；电力/制冷有余量；管理与业务网络按设计连通 |
| 回退 | 故障件隔离并走 RMA；端口或环境不符则不上架/不开工；使用备用节点须经变更批准 |
| 责任角色 | A：客户 IT/设施负责人；R：硬件、网络、系统工程师；C：供应商、安全、采购；I：服务方项目经理 |

#### P5 安装部署与基线固化

| 要素 | 内容 |
|---|---|
| 前置条件 | G3 放行；变更窗口、备份、账号、制品及回退路径齐备 |
| 输入 | 安装手册、锁定制品、哈希/签名、版本矩阵、网络策略、模型许可证 |
| 步骤 | ①备份原配置；②安装固件/驱动/运行时；③部署容器、编排和仓库；④导入并校验模型；⑤部署推理服务、网关、鉴权和监控；⑥健康检查、预热与冒烟；⑦导出配置基线和安装证据 |
| 产物 | 可运行平台、安装日志、SBOM/制品清单、配置基线、账号权限表 |
| 验收 | 重启后自动恢复；健康检查通过；版本与设计一致；安装过程可重复；无未授权外联 |
| 回退 | 按层回退镜像/模型/驱动；恢复配置快照；无法在窗口内恢复则切回原服务并关闭新入口 |
| 责任角色 | A：服务方交付经理；R：平台/系统工程师；C：客户 IT、安全、模型管理员；I：业务 Owner |

#### P6 应用联调与安全加固

| 要素 | 内容 |
|---|---|
| 前置条件 | 平台冒烟通过；接口、身份源、测试租户和测试数据可用 |
| 输入 | API 契约、调用链、权限矩阵、安全基线、RAG 数据与评测集 |
| 步骤 | ①联调 API、超时、重试与幂等；②接入 SSO/RBAC、限流和配额；③配置 RAG 权限过滤与引用；④实施加密、密钥、日志脱敏和审计；⑤测试提示注入、越权和数据泄露；⑥修复并复测 |
| 产物 | 联调记录、安全配置、权限表、问题清单、端到端测试报告 |
| 验收 | 关键流程全部通过；跨租户/越权测试失败即阻断；审计可追溯到用户、模型和请求；高危缺陷清零 |
| 回退 | 关闭问题接口/租户，回退到上一稳定版本；RAG 权限不可靠时禁用检索而非绕过授权 |
| 责任角色 | A：客户应用负责人；R：应用、平台、安全工程师；C：数据 Owner、业务专家、法务/合规；I：项目经理 |

#### P7 验收、灰度与上线

| 要素 | 内容 |
|---|---|
| 前置条件 | 联调完成；验收计划、基线、窗口、回退阈值和签字人确认 |
| 输入 | 验收用例、基准数据集、SLA/SLO、灾备方案、遗留风险清单 |
| 步骤 | ①执行功能/效果/性能/稳定性/安全测试；②执行备份恢复和故障切换；③封存结果；④小流量灰度；⑤观察错误率、时延、资源和质量；⑥批准全量或回退 |
| 产物 | 验收报告、缺陷与豁免、上线审批、灰度记录、最终回退包 |
| 验收 | 合同指标达标；P0/P1 缺陷清零；恢复目标验证；监控、告警和值班可用；业务签字 |
| 回退 | 触发阈值即停止放量，路由回旧系统/人工流程，恢复稳定版本；未签风险不得强行上线 |
| 责任角色 | A：客户业务 Owner；R：测试经理、发布经理；C：运维、安全、架构师、业务专家；I：全体干系人 |

#### P8 移交与持续维保

| 要素 | 内容 |
|---|---|
| 前置条件 | 上线稳定期结束；维保合同、SLA 和联系树生效 |
| 输入 | 架构与配置、资产、账号、监控、SOP、备份、已知问题 |
| 步骤 | ①培训管理员和一线支持；②交接台账、告警和工单；③演练常见故障与升级回滚；④按周期巡检、补丁和容量复盘；⑤跟踪 SLO、模型/RAG 质量和成本；⑥执行变更评审 |
| 产物 | 移交签字单、培训记录、巡检/SLA 月报、变更和事故记录 |
| 验收 | 客户可独立完成启停、扩缩、告警确认、备份恢复和报障；文档与生产一致 |
| 回退 | 接管演练失败则延长陪跑；重大升级失败回滚版本；超出容量/服务范围转新变更或新项目 |
| 责任角色 | A：客户运维负责人；R：客户运维、服务台/维保工程师；C：平台、安全、业务 Owner；I：管理层 |

#### P9 退场与数据处置

| 要素 | 内容 |
|---|---|
| 前置条件 | 合同终止/系统替换获批；保留期限和法律冻结要求确认 |
| 输入 | 资产、账号、数据、模型、密钥、备份、许可证和制品台账 |
| 步骤 | ①停止入口并封存最终备份；②按约定导出配置/数据；③撤销账号、证书、令牌和网络规则；④擦除工作盘、缓存、日志和备份；⑤归还/处置资产与许可证；⑥双人复核并归档证据 |
| 产物 | 退场报告、资产归还单、账号撤销记录、擦除/销毁证明、例外清单 |
| 验收 | 无有效服务账号和外部入口；资产逐项闭环；数据处置由 Owner 签字；依法保留项有隔离与期限 |
| 回退 | 发现法律冻结或未授权删除风险立即停止擦除；从封存备份恢复仅须经数据 Owner 和安全双批准 |
| 责任角色 | A：客户 IT/数据 Owner；R：系统与安全管理员；C：法务/合规、服务方交付经理；I：业务 Owner、审计 |

## 5. 场景优先级

### 5.1 先过硬门槛

以下任一项为“否”，场景不得进入真实数据 PoC：

- 有明确业务 Owner 和用户；
- 数据权属、用途与处理地域可确认；
- 能建立不少于一项可复测的当前基线；
- 错误可被人工发现或不会直接造成不可逆高损失；
- 在预算、时间和机房约束内存在可行技术路线；
- 模型、数据和软件许可证允许目标用途。

### 5.2 加权评分矩阵

每项按 1—5 分评分，权重按下表百分比换算为小数；百分制总分为：

```text
场景总分 = Σ（单项评分 × 权重小数）÷ 5 × 100
```

例如业务价值 4 分、权重 20%，该项贡献 `4 × 0.20 ÷ 5 × 100 = 16` 分。全部维度均为 5 分时总分为 100。**风险可控性、数据就绪度任一项低于 3 分，即使总分高也不得列为首批生产场景。**

| 维度 | 权重 | 1 分 | 3 分 | 5 分 | 证据 |
|---|---:|---|---|---|---|
| 业务价值 | 20% | 收益不明 | 局部提效 | 有财务/战略量化收益 | 财务基线、业务 KPI |
| 用户覆盖/频次 | 10% | 低频少数人 | 部门级 | 高频跨部门 | DAU、任务量 |
| 技术适配度 | 15% | 模型能力弱 | 需较多工程 | 成熟任务、最小改造 | PoC/公开基准 |
| 数据就绪度 | 15% | 无权属/质量差 | 需治理 | 已授权、可评测、可更新 | 数据清单、质量报告 |
| 风险可控性 | 15% | 不可逆且无复核 | 可加人工复核 | 低风险、可回退 | 风险评审 |
| 集成复杂度 | 10% | 多核心系统改造 | 2—3 个接口 | 独立或标准接口 | 系统依赖图 |
| 交付时效 | 5% | 超过 6 月 | 2—3 月 | 4 周内闭环 | 项目估算 |
| 可复用性 | 5% | 一次性 | 部门复用 | 可平台化推广 | 路线图 |
| 总拥有成本 | 5% | 超预算且不确定 | 预算内但余量小 | 成本清晰且可扩展 | TCO/BOM |

## 6. 路线边界速查

| 路线 | 适用条件 | 不适用/升级信号 | 主要风险 |
|---|---|---|---|
| PoC 单机 | 验证价值、低并发、允许停机 | 不作为生产 SLA 依据；生产负载需重新压测 | 将实验配置误当生产配置 |
| 生产单机 | 负载可控、允许维护停机、预算有限 | 节点故障不可接受或容量接近上限时升级多副本 | 单点故障 |
| 多副本推理 | 模型可单卡/单机容纳，要求扩缩容与 HA | 单实例放不下或跨卡通信成为瓶颈时考虑并行 | 状态与缓存一致性 |
| 多机多 GPU 并行 | 大模型单节点放不下或单副本吞吐不足 | 网络/RDMA、拓扑和运维能力不足时不应强上 | 通信瓶颈、故障域扩大 |
| RAG | 知识经常更新、需私域事实与引用 | 检索不命中、权限模型不清时先治理；不能用 RAG 修复推理能力缺陷 | 越权检索、错误引用 |
| LoRA/QLoRA | 需稳定格式、风格、术语或任务行为，且有高质量样本 | 知识频繁更新优先 RAG；样本/评测不足则停止 | 过拟合、遗忘、数据许可 |
| 全量训练/持续预训练 | 大规模专域语料、基础能力确有缺口、算力与团队成熟 | 无明确增益基线、预算或版权不清不得进入 | 成本极高、不可复现、许可风险 |
| 公有模型 API | 数据可外发、追求快速验证、接受供应商边界 | 隐私/地域/离线硬约束时改本地 | 锁定、留存、跨境 |
| 商业本地模型 | 需要厂商支持、许可证和稳定版本 | 许可证成本或硬件绑定不可接受时改开源/自有 | 授权范围、续费 |
| 开源/开放权重模型 | 需自主部署和可控栈，团队能运维 | 许可证不允许商用或缺乏维护能力时禁用 | 供应链、支持责任 |
| 自有模型 | 有独特数据与长期模型团队 | 仅为“自主可控”但无持续投入时不宜采用 | 全生命周期成本 |

## 7. RACI

## 8. 停止条件、暂停条件与恢复门槛

### 8.1 项目级红线

出现下列任一情况，任何成员均可提出停工；客户项目负责人和服务方项目经理必须立即冻结相关操作并升级：

| 编号 | 停止条件 | 立即动作 | 恢复门槛 | 最终决策人 |
|---|---|---|---|---|
| S01 | 数据无权属/用途授权，或实际级别高于申报 | 停止复制、索引、训练；隔离已导入数据并保全审计 | 数据 Owner 与法务/合规书面批准；完成处置 | DPO |
| S02 | 模型、数据或软件许可证不明/不允许目标用途 | 禁止下载、导入、部署或分发 | 获得有效授权或替换制品 | DPO/采购 |
| S03 | 发现未批准的外联、跨境或第三方传输 | 阻断网络、轮换凭据、启动安全事件流程 | 查清影响范围，修复并经安全批准 | SEC |
| S04 | 发生跨租户访问、敏感数据泄露或高危漏洞 | 下线入口、保全证据、通知响应团队 | 高危清零、复测通过、剩余风险签字 | SEC |
| S05 | 机房电力、散热、消防或硬件状态不安全 | 断电/停止上架与压测 | 设施整改和验机报告通过 | CIT/设施负责人 |
| S06 | 变更无批准、无备份、无回退或超出窗口 | 停止变更，恢复原配置 | 变更单、备份和回退演练齐备 | CPM/CIT |
| S07 | PoC 达到时间、预算或试验轮次上限仍未达最低指标 | 冻结新增调优，形成失败分析 | 业务 Owner 批准缩目标、换路线或追加预算 | BO |
| S08 | 关键假设失效导致 BOM/SLA 偏差超批准范围 | 暂停采购或上线 | 重做容量/商务评审并批准变更 | 项目委员会 |
| S09 | 生产 P0/P1 缺陷未关闭，或验收证据不可复现 | 禁止上线/放量 | 缺陷关闭并独立复测 | BO/TEST |
| S10 | 无可用监控、告警、值班或回退路径 | 停止灰度或回旧系统 | 值班演练、告警和回退测试通过 | CIT |
| S11 | 客户关键角色长期缺席或依赖逾期跨越关键路径 | 暂停受影响工作并记录成本/工期影响 | 新负责人和新计划获双方确认 | 双方项目经理 |
| S12 | 要求绕过安全控制、伪造测试数据/证据或隐瞒风险 | 立即拒绝并升级治理/审计 | 合法合规方案和管理层书面确认 | 双方管理层/合规 |
