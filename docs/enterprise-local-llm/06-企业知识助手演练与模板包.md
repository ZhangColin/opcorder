# 企业知识助手从零演练：PoC → 单机生产 → HA 集群

> **案例目标**：员工通过 OpenAI 兼容 API 查询企业制度；回答必须携带出处，且只能检索调用者有权限访问的文档。示例栈为 Linux、容器、vLLM、Embedding/Rerank 服务、Qdrant 与 API 网关。组件可替换，但验收口径不变。
>
> **命令使用声明**：本章所有命令均为**示例命令**，其中 `<...>` 均为必须结合客户环境、兼容矩阵和审批结果替换的占位符。示例不能直接用于所有环境，也不构成厂商兼容性或生产可用性承诺。执行前应在非生产环境验证，并锁定版本、镜像摘要和回退方案。
>
> 模型、驱动、镜像和价格等时效信息必须记录**核验日期、厂商官方来源、许可证与 SHA-256**。模型权重、业务数据和密钥不得写入镜像、脚本或 Git。

## 1. 三路线与升级门槛

| 路线 | 目的 | 推荐拓扑 | 可接受故障域 | 进入条件 | 退出/升级条件 |
|---|---|---|---|---|---|
| PoC | 证明效果、容量与集成可行 | 单 GPU 主机，Compose，可同机部署组件 | 主机故障即停服 | 已确认数据授权、模型许可和验收问题集 | 核心问题集达标且业务方确认价值；不得直接承载生产流量 |
| 单机生产 | 小规模正式服务 | 双电源服务器；推理、向量库、网关容器化；独立备份目标 | 节点故障需人工恢复 | PoC 签收、安全整改完成、备份恢复通过 | SLA 要求自动切换，或峰值持续超过安全容量 70% |
| HA 集群 | 节点故障下持续服务与横向扩容 | 至少 3 个控制节点、至少 2 个 GPU 工作节点、双负载均衡、HA 存储/数据库 | 单节点或单副本故障不影响 SLO | 单机基线稳定，网络、存储和调度能力成熟 | 出现跨机房 RTO/RPO 要求时进入双集群灾备设计 |

### 1.1 示例目录与变量

以下仅演示目录规划方式，路径、用户和发布编号必须替换：

```bash
# 示例命令：请替换全部尖括号占位符
export RELEASE="<RELEASE_ID>"
export ROOT="<INSTALL_ROOT>"
export MODEL_PATH="<CHAT_MODEL_PATH>"
export EMBED_MODEL_PATH="<EMBEDDING_MODEL_PATH>"
export MODEL_SHA256="<APPROVED_MODEL_SHA256>"
sudo install -d -m 0750 "${ROOT}"/{compose,config,data,logs,backup,evidence}
```

### 1.2 统一准入红线

模型或数据许可未确认、测试数据含未经批准的敏感信息、制品校验失败、管理员默认密码未改、无可验证回退点，任一项成立即停止。

### 1.3 示例工具适配契约

本章使用的 `<KB_CLI_PATH>`、`<EVAL_TOOL_PATH>`、`<LOADTEST_TOOL_PATH>` 和 `<TRAFFIC_CONTROL_TOOL>` 是**客户项目必须实现或选定的适配器**，不是假定环境中已存在的命令。进入演练前，实施方必须把占位符替换为批准的实际工具，并用以下契约做冒烟测试；做不到则不得声称演练可执行。

| 适配器 | 最低输入契约 | 最低输出契约 | 可替换实现 |
|---|---|---|---|
| `KB_CLI` | `ingest` 接收源目录、collection、Embedding、切分、元数据；`query` 接收 collection、问题、Top-K、Rerank-N 和调用者身份 | JSONL；每个文档含 `document_id/version/hash/chunk_id/acl/source_uri`；查询含候选分数、引用和权限判定 | 项目自有摄取 CLI、向量库 SDK 封装或受控摄取 API |
| `EVAL_TOOL` | 黄金集 JSONL：`id/input/expected/allowed_sources/forbidden_sources/tags`；支持指定 endpoint 和版本 | JSON/JSONL：逐样本结果及任务成功率、引用正确率、拒答、越权、分桶统计 | 项目测试程序、pytest、RAG 评测框架或客户测试平台 |
| `LOADTEST_TOOL` | endpoint、鉴权引用、并发阶梯、输入/输出长度分布、持续时长、超时和停止阈值 | 原始样本或直方图；RPS、输入/输出 TPS、TTFT/TPOT P50/P95/P99、错误、队列和资源时间线 | k6、Locust、JMeter 或客户压测平台 |
| `TRAFFIC_CONTROL_TOOL` | 服务、稳定版/候选版、权重、命名空间和变更单 | 修改前后路由、操作者、时间、可验证回退命令 | 企业 API 网关、服务网格、Gateway API 或受控发布平台 |

黄金集最小示例：

```json
{"id":"q-001","input":"<QUESTION>","expected":{"must_cite":true,"answer_facts":["<FACT>"]},"allowed_sources":["doc-policy-v3"],"forbidden_sources":["doc-finance-restricted"],"tags":["zh-CN","policy","acl"]}
```

适配器放行检查：

1. `--help` 或 API 契约已归档，退出码非零代表失败，不得静默跳过样本。
2. 所有输出带模型、索引、提示模板、数据集和工具版本；时间使用统一时钟。
3. 鉴权只引用密钥管理系统或受控 Secret，不把令牌写入命令行历史、结果或日志。
4. 在 3–5 条合成样本上证明成功、失败、超时、越权和取消路径都能被记录。
5. `TRAFFIC_CONTROL_TOOL` 先执行只读/预览模式；生产写入必须绑定变更单、双人复核和自动回退阈值。
6. 若使用第三方评测框架，先确认不会把提示词、文档或输出发送到外部服务。

## 2. 路线 A：低成本 PoC

### A1. 前置检查与基线留证

- **目标**：确认 GPU、驱动、磁盘、端口和模型文件可用。
- **示例命令**：

```bash
# 示例命令：GPU 工具、路径、端口和哈希均须按环境替换
<GPU_SMI_COMMAND> --query-gpu=<GPU_QUERY_FIELDS> --format=<OUTPUT_FORMAT>
free -h
df -h "<INSTALL_ROOT>" "<MODEL_ROOT>"
ss -lnt | grep -E ':(<LLM_PORT>|<VECTOR_DB_PORT>|<API_PORT>)\b' || true
sha256sum "<CHAT_MODEL_PATH>"/* > "<EVIDENCE_DIR>/model.sha256"
grep -F "<APPROVED_MODEL_SHA256>" "<EVIDENCE_DIR>/model.sha256"
```

- **检查**：GPU 无 Xid 或未纠正 ECC 错误；可用显存满足“权重 + KV Cache + 运行时余量”；模型哈希与审批单一致；端口无冲突。
- **常见错**：GPU 管理命令失败通常与驱动、固件、内核或容器运行时不匹配有关；哈希不一致时不得以重新计算并覆盖审批值的方式掩盖，应隔离制品、重新传输并复核来源。
- **回退**：本步骤不修改宿主机；隔离不合格制品。若此前已变更驱动，应按已审批的驱动快照或回退手册恢复。
- **准入**：基线表、许可证结论、哈希证据齐全，容量初算有审核人。

### A2. 启动推理服务

- **目标**：提供仅绑定到受控接口的 OpenAI 兼容 API。
- **示例命令**：

```bash
# 示例命令：镜像、摘要、运行时参数、地址和端口必须经过兼容性验证
docker run -d --name "<LLM_CONTAINER_NAME>" \
  --gpus "<GPU_DEVICE_SELECTOR>" \
  --restart=no \
  --shm-size="<SHM_SIZE>" \
  -p "<BIND_ADDRESS>:<HOST_LLM_PORT>:<CONTAINER_LLM_PORT>" \
  -v "<CHAT_MODEL_PATH>:/model:ro" \
  "<PRIVATE_REGISTRY>/<VLLM_IMAGE>:<VERSION>@sha256:<IMAGE_DIGEST>" \
  --model /model \
  --served-model-name "<SERVED_MODEL_NAME>" \
  --dtype "<DTYPE>" \
  --max-model-len "<MAX_MODEL_LENGTH>" \
  --gpu-memory-utilization "<GPU_MEMORY_RATIO>"

curl -fsS "http://<LLM_SERVICE_HOST>:<LLM_SERVICE_PORT>/v1/models"
curl -fsS "http://<LLM_SERVICE_HOST>:<LLM_SERVICE_PORT>/v1/chat/completions" \
  -H "Content-Type: application/json" \
  -d '{"model":"<SERVED_MODEL_NAME>","messages":[{"role":"user","content":"<TEST_PROMPT>"}],"max_tokens":<MAX_OUTPUT_TOKENS>}'
```

- **检查**：健康请求返回约定的 2xx；首个请求预热后记录 TTFT、tokens/s、显存峰值和错误率。
- **常见错**：OOM 时先降低上下文、并发或显存利用率，再评估经批准的量化；不要在一次复测中同时修改多个参数。模型架构不受支持时，应切换到兼容矩阵中已验证的引擎版本。
- **回退**：

```bash
# 示例命令：仅删除本次 PoC 容器，不删除权重和证据
docker rm -f "<LLM_CONTAINER_NAME>"
```

- **准入**：连续约定次数请求无 5xx；输出格式符合接口契约；显存峰值保留至少 10% 或项目约定余量。

### A3. 建立最小 RAG 链路

- **目标**：完成文档解析、切分、向量化、检索、引用；原文不可变，索引可重建。
- **示例命令**：

```bash
# 示例命令：镜像摘要、目录、模型及切分参数须按评测结果替换
docker run -d --name "<VECTOR_DB_CONTAINER>" \
  --restart=no \
  -p "<BIND_ADDRESS>:<HOST_VECTOR_PORT>:<CONTAINER_VECTOR_PORT>" \
  -v "<VECTOR_DATA_DIR>:/qdrant/storage" \
  "<PRIVATE_REGISTRY>/<VECTOR_DB_IMAGE>:<VERSION>@sha256:<IMAGE_DIGEST>"

curl -fsS "http://<VECTOR_DB_HOST>:<VECTOR_DB_PORT>/readyz"
sha256sum "<SOURCE_DOCUMENT_DIR>"/* > "<EVIDENCE_DIR>/source.sha256"

"<KB_CLI_PATH>" ingest \
  --source "<SOURCE_DOCUMENT_DIR>" \
  --collection "<POC_COLLECTION_NAME>" \
  --embedding-model "<EMBEDDING_MODEL_PATH>" \
  --chunk-size "<CHUNK_SIZE>" \
  --chunk-overlap "<CHUNK_OVERLAP>" \
  --metadata-fields "<APPROVED_METADATA_FIELDS>"

"<KB_CLI_PATH>" query \
  --collection "<POC_COLLECTION_NAME>" \
  --question "<GOLDEN_QUESTION>" \
  --top-k "<RETRIEVAL_TOP_K>" \
  --rerank-top-n "<RERANK_TOP_N>" \
  --show-citations
```

- **检查**：抽样核对文本、页码、版本、ACL 和引用地址；重复导入不产生重复文档；无答案问题明确回复“证据不足”。
- **常见错**：扫描 PDF 无文本时应走获批 OCR；乱码先修复编码；Embedding 维度变化必须新建 collection；ACL 不能只在前端过滤。
- **回退**：保留原文与导入清单，删除本次 PoC collection 后按清单重建；禁止直接篡改向量库中的原文。
- **准入**：黄金问题集的检索命中率和引用正确率达到 PoC 约定值；越权测试 0 泄露。

### A4. 评测、压测与 PoC 签收

- **目标**：以证据决定是否生产化，而非凭演示观感。
- **示例命令**：

```bash
# 示例命令：工具路径、数据集、接口和负载参数须替换
"<EVAL_TOOL_PATH>" run \
  --dataset "<GOLDEN_DATASET_PATH>" \
  --endpoint "http://<POC_API_HOST>:<POC_API_PORT>/v1" \
  --out "<EVIDENCE_DIR>/eval.json"

"<LOADTEST_TOOL_PATH>" run \
  --endpoint "http://<POC_API_HOST>:<POC_API_PORT>/v1" \
  --concurrency "<CONCURRENCY_STEPS>" \
  --duration "<TEST_DURATION>" \
  --out "<EVIDENCE_DIR>/load.json"
```

- **检查**：任务成功率、引用正确率、拒答准确率、P50/P95 TTFT、P95 总时延、吞吐、错误率、GPU 峰值均有原始记录。
- **常见错**：开发文档混入评测集造成泄漏；只报告平均时延；压测问题长度与生产分布不一致。
- **回退**：回到登记过的模型、切分和检索参数基线，单变量复测；指标不达标则停止生产化。
- **准入**：业务、技术、安全三方签署 PoC 结论，明确不达标项、生产差距和预算上限。

## 3. 路线 B：单机生产

### B1. 主机、安全与持久化准备

- **目标**：从临时容器升级为可审计、可恢复的服务。
- **示例命令**：

```bash
# 示例命令：时间服务、服务账号、目录和防火墙工具须按系统基线替换
sudo timedatectl set-ntp "<NTP_ENABLED_VALUE>"
sudo useradd --system --home "<INSTALL_ROOT>" --shell "<NOLOGIN_SHELL>" "<SERVICE_ACCOUNT>"
sudo chown -R "<SERVICE_ACCOUNT>:<SERVICE_GROUP>" \
  "<DATA_DIR>" "<LOG_DIR>" "<BACKUP_DIR>"
sudo chmod 0750 "<CONFIG_DIR>" "<DATA_DIR>" "<LOG_DIR>" "<BACKUP_DIR>"
sudo <FIREWALL_EXPORT_COMMAND> > "<EVIDENCE_DIR>/firewall-before.txt"
systemctl is-active "<CONTAINER_RUNTIME_SERVICE>"
```

- **检查**：管理、业务、存储网络分区明确；NTP/DNS 正常；数据盘和日志盘告警已设置；密钥来自 Vault/KMS，或使用符合客户制度的受控 Secret 文件。
- **常见错**：容器以 root 运行并可写宿主机；数据库数据放在容器临时层；将 GPU API 暴露到办公网。
- **回退**：使用变更前导出的防火墙配置恢复规则；卸载新挂载前确认无进程写入。
- **准入**：安全基线扫描无未豁免高危项，资产编号、位置和责任人已登记。

### B2. 固化版本并发布服务组

- **目标**：以固定 digest、健康检查、资源限制和自动重启策略部署服务。
- **示例命令**：

```bash
# 示例命令：Compose 只是可选实现；环境文件和渲染后的配置不得进入证据包或版本库
cd "<COMPOSE_DIR>"
# 只做语法/变量完整性校验，不把插值后的配置输出到终端或文件
docker compose --env-file "<PROTECTED_ENV_FILE>" config --quiet
docker compose pull
docker inspect --format '{{index .RepoDigests 0}}' \
  "<PRIVATE_REGISTRY>/<SERVICE_IMAGE>:<VERSION>"
docker compose up -d --wait

curl -fsS "https://<PRODUCTION_API_FQDN>/<LIVE_PATH>"
curl -fsS "https://<PRODUCTION_API_FQDN>/<READY_PATH>"
```

- **检查**：镜像 digest 与制品单一致；TLS 证书链正确；`live` 不依赖下游，`ready` 验证模型和向量库；日志不含提示词正文、Token 或个人信息。证据目录权限不高于 `0750`，交付前使用客户批准的敏感信息扫描工具检查并由双人复核。
- **常见错**：只锁 tag 未锁 digest；健康检查调用昂贵生成接口；把 `docker compose config` 的插值结果重定向到所谓“redacted”文件——文件名不会脱敏，可能直接泄露数据库、OIDC 或 KMS 凭据。
- **回退**：

```bash
# 示例命令：切换到经验证的上一发布目录和摘要
cd "<CURRENT_RELEASE_COMPOSE_DIR>"
docker compose down
cd "<PREVIOUS_RELEASE_COMPOSE_DIR>"
docker compose up -d --wait
```

数据库迁移应使用向后兼容的 expand/contract 策略，不得假设容器回滚会自动回滚数据。

- **准入**：预生产冒烟测试通过，连续约定观察期无异常重启，配置差异完成双人复核。

### B3. 接入鉴权、限流和权限检索

- **目标**：使用 SSO/OIDC 鉴权，并在服务端检索前强制执行租户与部门 ACL。
- **示例命令**：

```bash
# 示例命令：测试 Token 必须来自隔离测试账号，不得在历史记录中留下真实凭据
curl -i "https://<PRODUCTION_API_FQDN>/<CHAT_API_PATH>"
curl -fsS "https://<PRODUCTION_API_FQDN>/<CHAT_API_PATH>" \
  -H "Authorization: Bearer <SHORT_LIVED_TEST_TOKEN>" \
  -H "Content-Type: application/json" \
  -d @"<ALLOWED_REQUEST_FIXTURE>"

"<SECURITY_TEST_TOOL>" \
  --cases "<ACL_TEST_CASES_PATH>" \
  --endpoint "https://<PRODUCTION_API_FQDN>"
```

- **检查**：无 Token 返回 401、无权限返回 403；检索过滤包含 `tenant_id` 和 ACL；每用户/应用限流返回 429；审计日志能关联请求 ID、用户、模型和文档 ID，但不记录敏感正文。
- **常见错**：共享服务账号导致无法审计；只在生成后删除敏感引用；信任客户端传入的部门字段。
- **回退**：网关摘除新路由并恢复上一版本配置；发现越权时立即停流、保全审计记录并启动安全事件响应。
- **准入**：正向、反向、跨部门、过期 Token 和提示注入测试全部通过。

### B4. 备份恢复与上线

- **目标**：证明配置、元数据、向量索引和原文能在目标时间内恢复。
- **示例命令**：

```bash
# 示例命令：备份工具、加密密钥引用和隔离恢复位置须按方案替换
"<BACKUP_TOOL>" create \
  --config "<BACKUP_CONFIG_PATH>" \
  --output "<BACKUP_TARGET>/<RELEASE_ID>"

sha256sum "<BACKUP_TARGET>/<RELEASE_ID>"/* \
  > "<EVIDENCE_DIR>/backup.sha256"

"<RESTORE_TOOL>" verify \
  --backup "<BACKUP_TARGET>/<RELEASE_ID>" \
  --target "<ISOLATED_RESTORE_TARGET>" \
  --isolated
```

- **检查**：备份加密且异机保存；恢复环境不得连接生产；恢复后文档数、哈希、ACL 和黄金问题结果一致；实测 RPO/RTO 达标。
- **常见错**：只验证“备份任务成功”而不恢复；只备向量索引不备原文和版本；恢复演练误连生产。
- **回退**：上线异常时由网关摘流，恢复上个 release 及其兼容快照；超过回退窗口升级为事故。
- **准入**：恢复演练签字；长稳测试通过；峰值 GPU 显存、CPU、RAM、磁盘 IO 均保留至少 20% 或约定余量；监控、告警和值班表生效。

## 4. 路线 C：HA 集群

### C1. 集群与故障域验收

- **目标**：确认控制面、GPU 节点、网络、存储和负载均衡无单点。
- **示例命令**：

```bash
# 示例命令：kubectl 上下文必须先确认指向目标非生产或已审批集群
kubectl --context "<CLUSTER_CONTEXT>" get nodes -o wide
kubectl --context "<CLUSTER_CONTEXT>" get storageclass
kubectl --context "<CLUSTER_CONTEXT>" get pods -A \
  | grep -E '<GPU_OPERATOR_PATTERN>|<DEVICE_PLUGIN_PATTERN>'
kubectl --context "<CLUSTER_CONTEXT>" describe node "<GPU_NODE_NAME>" \
  | grep -A "<CONTEXT_LINES>" 'Allocatable'
kubectl --context "<CLUSTER_CONTEXT>" auth can-i create deployments \
  -n "<NAMESPACE>" \
  --as="system:serviceaccount:<NAMESPACE>:<DEPLOYER_SERVICE_ACCOUNT>"
```

- **检查**：至少 3 个控制节点跨故障域；至少 2 个 GPU 节点；GPU 资源可调度；LB/VIP 双实例；存储明确 RPO/RTO；NTP、MTU 和 DNS 一致。
- **常见错**：两个推理副本落到同一节点；共享存储本身是单点；GPU 型号或显存不同却使用同一调度池。
- **回退**：不接业务流量，撤销本次 namespace 和临时 StorageClass；底层问题交回集群责任方整改。
- **准入**：节点、LB、存储任一单点故障演练均得到预期结果。

### C2. 声明式部署推理与 RAG

- **目标**：通过不可变镜像、反亲和、PDB 和滚动策略发布至少两个独立副本。
- **示例命令**：

```bash
# 示例命令：Chart、values、摘要、上下文和超时须结合环境替换
kubectl --context "<CLUSTER_CONTEXT>" create namespace "<NAMESPACE>" \
  --dry-run=client -o yaml \
  | kubectl --context "<CLUSTER_CONTEXT>" apply -f -

helm --kube-context "<CLUSTER_CONTEXT>" upgrade --install "<RELEASE_NAME>" \
  "<CHART_PATH>" \
  -n "<NAMESPACE>" \
  -f "<PRODUCTION_VALUES_PATH>" \
  --set-string image.digest="sha256:<IMAGE_DIGEST>" \
  --atomic \
  --timeout "<DEPLOY_TIMEOUT>"

kubectl --context "<CLUSTER_CONTEXT>" rollout status \
  deployment/"<API_DEPLOYMENT>" -n "<NAMESPACE>" --timeout="<ROLLOUT_TIMEOUT>"
kubectl --context "<CLUSTER_CONTEXT>" get pods -n "<NAMESPACE>" -o wide
kubectl --context "<CLUSTER_CONTEXT>" get pdb,hpa,networkpolicy -n "<NAMESPACE>"
```

- **检查**：副本跨节点和故障域；readiness 在模型加载完成后才放流；PDB 防止同时驱逐；NetworkPolicy 默认拒绝；Secret 不在 Helm values 明文中。
- **常见错**：模型加载时间超过探针阈值导致重启环；HPA 只看 CPU；滚动升级时 GPU 余量不足导致新 Pod Pending。
- **回退**：

```bash
# 示例命令：回退版本必须已验证，数据 schema 必须向后兼容
helm --kube-context "<CLUSTER_CONTEXT>" rollback \
  "<RELEASE_NAME>" "<PREVIOUS_REVISION>" \
  -n "<NAMESPACE>" --wait --timeout "<ROLLBACK_TIMEOUT>"
```

- **准入**：所有副本 Ready 并跨故障域分布；资源请求/限制与压测基线一致；镜像扫描无未豁免高危项。

### C3. 扩缩容、流量治理与灰度

- **目标**：基于队列、并发、TTFT 和 GPU 利用率扩容；新版本先承接小比例流量。
- **示例命令**：

```bash
# 示例命令：灰度清单、权重、观察窗和阈值须经变更审批
kubectl --context "<CLUSTER_CONTEXT>" apply \
  -n "<NAMESPACE>" -f "<CANARY_MANIFEST_PATH>"
kubectl --context "<CLUSTER_CONTEXT>" get deploy -n "<NAMESPACE>" -w

"<TRAFFIC_CONTROL_TOOL>" set-weight \
  --service "<CHAT_SERVICE>" \
  --stable "<STABLE_WEIGHT>" \
  --canary "<CANARY_WEIGHT>"

"<EVAL_TOOL_PATH>" compare \
  --baseline "<BASELINE_RELEASE>" \
  --candidate "<CANARY_RELEASE>"

"<TRAFFIC_CONTROL_TOOL>" set-weight \
  --service "<CHAT_SERVICE>" \
  --stable "<ROLLBACK_STABLE_WEIGHT>" \
  --canary "<ROLLBACK_CANARY_WEIGHT>"
```

- **检查**：灰度和稳定版使用同一脱敏评测集；关注 P95 TTFT、5xx、拒答率、引用正确率和队列长度；扩容时间包含权重拉取与预热。
- **常见错**：用平均 GPU 利用率掩盖队列；权重从公网临时下载；自动缩容终止长请求；状态会话未做连接排空。
- **回退**：灰度权重立即置为 0，保留 Pod 和证据用于分析；确认没有不兼容写入后再删除候选版本。
- **准入**：灰度观察窗内性能和质量不劣于约定阈值，扩缩容无请求丢失。

### C4. HA、容量与恢复演练

- **目标**：验证节点、Pod、LB、存储故障和版本回退。
- **示例命令**：

```bash
# 示例命令：先只读核对副本，再删除变更单中明确批准的一个 Pod
TARGET_POD="<ONE_APPROVED_READY_POD_NAME>"

kubectl --context "<CLUSTER_CONTEXT>" get pods \
  -n "<DEDICATED_TEST_NAMESPACE>" \
  -l "app.kubernetes.io/name=<CHAT_WORKLOAD_LABEL>" \
  -o wide

# 至少两个目标副本必须处于 Ready；输出数字须人工复核并写入证据
kubectl --context "<CLUSTER_CONTEXT>" get pods \
  -n "<DEDICATED_TEST_NAMESPACE>" \
  -l "app.kubernetes.io/name=<CHAT_WORKLOAD_LABEL>" \
  -o jsonpath='{range .items[*]}{.metadata.name}{"\t"}{.status.conditions[?(@.type=="Ready")].status}{"\n"}{end}'

# 只检查变更单批准的单个 Pod；不得把共享 Deployment 标签用于删除
kubectl --context "<CLUSTER_CONTEXT>" get pod \
  -n "<DEDICATED_TEST_NAMESPACE>" \
  "${TARGET_POD}" -o wide

kubectl --context "<CLUSTER_CONTEXT>" delete pod \
  -n "<DEDICATED_TEST_NAMESPACE>" \
  "${TARGET_POD}" \
  --wait=false

kubectl --context "<CLUSTER_CONTEXT>" get pods \
  -n "<DEDICATED_TEST_NAMESPACE>" -o wide -w

"<LOADTEST_TOOL_PATH>" run \
  --endpoint "https://<PRODUCTION_API_FQDN>/<API_BASE_PATH>" \
  --concurrency "<APPROVED_PEAK_CONCURRENCY>" \
  --duration "<HA_TEST_DURATION>" \
  --out "<EVIDENCE_DIR>/ha-node-loss.json"
```

- **检查**：先确认 PDB、至少两个跨故障域的 Ready 副本、N+1 容量、外部持久化和告警；`TARGET_POD` 必须与变更单逐字一致，且删除前确认它不是唯一 Ready 副本。压测应在删除前启动并覆盖删除、接管、恢复全过程；故障期间成功率、P95、错误预算和恢复时长满足 SLO；新 Pod 进入 Ready 后再结束观察。
- **节点级演练边界**：通用手册不提供可复制的 `drain --delete-emptydir-data` 或断电命令。节点故障演练只能在**专属测试集群或经资产清单证明无其他租户/工作负载的专属节点**执行，必须先检查全部 Pod、`emptyDir`、本地 PV、PDB 和维护窗口，再使用客户批准的混沌平台或节点 Runbook。共享集群不得用节点级破坏命令模拟故障。
- **常见错**：将“Pod 重建成功”误认为业务无损；未预留 N+1 GPU 容量；使用共享 Deployment 标签一次删除全部副本；删除带本地状态的 Pod；没有停止条件。
- **回退**：达到停止阈值立即停止压测和故障注入、把网关流量切回健康副本；若目标副本未自动恢复，使用锁定版本重新部署并验证 Ready。数据恢复只能按已验证的存储/数据库 Runbook 执行，不能把 `uncordon` 当作已删除数据的恢复手段。
- **准入**：单 GPU 节点失效时仍可承载约定峰值；RTO/RPO、告警到达、值班响应和复盘记录均达标。

| TPS | Token 吞吐 | 必须明确按单请求或全服务、输入或输出统计 | 不等于每秒请求数 | 容量规划 |
