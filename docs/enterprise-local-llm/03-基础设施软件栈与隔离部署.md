# 基础设施与分层软件平台部署

> 本章适用于 PoC 单机、生产单机及多节点推理集群。执行原则：**先冻结兼容矩阵，再安装；先验证单卡/单机，再进入容器与编排；所有制品可追溯、可校验、可回滚。**具体型号、版本和支持状态变化较快，实施前应记录“核验日期、厂商官方兼容文档链接、验证人”。

## 1. 实施阶段与责任

| 阶段 | 前置/输入 | 关键操作 | 产物与验收 | 失败回退 | 主责 |
|---|---|---|---|---|---|
| 收货验机 | BOM、序列号、机房条件 | 外观、部件、带外管理、烧机 | 验机单；无硬件告警 | 隔离故障件、启动 RMA | 硬件供应商/实施方 |
| 基础系统 | 已验机服务器、网络规划 | 固件、Linux、安全基线、时钟/DNS | OS 基线报告 | 恢复固件配置或系统镜像 | 实施方/客户 IT |
| 加速栈 | 冻结兼容矩阵 | 驱动、运行时、通信库、单卡测试 | 设备与算子测试报告 | 回退上一已验证组合 | 实施方 |
| 容器与编排 | 加速栈通过 | 容器运行时、设备插件、调度 | 容器内可见设备；调度通过 | 退回裸机定位 | 平台团队 |
| 推理与接入 | 模型许可、容量参数 | 引擎、模型仓库、网关、鉴权限流 | API、性能、安全基线 | 蓝绿切回旧版本 | AI/平台团队 |

停止条件：供电或散热不满足设计值、固件存在重大告警、设备持续掉卡/ECC 不可纠正错误、版本组合无官方支持依据、模型许可证不允许目标用途时，不得进入生产部署。

## 2. 基础设施验机

### 2.1 上架前检查

1. 对照采购 BOM 核对服务器型号、CPU、内存条数量与频率、GPU/加速卡型号和数量、NVMe/RAID、网卡/HBA、冗余电源、导轨及序列号；拍照并录入资产台账。
2. 检查运输损伤、风扇/散热器松动、卡扣与供电线、液冷接头和漏液检测；禁止在包装或接口异常时通电。
3. 核算机柜承重、U 位、A/B 路电源、PDU 插座与单路额定功率。峰值功率及散热能力按设计余量核定，不以铭牌平均功耗替代。
4. 确认管理网、业务网、存储网和集群高速网络的 VLAN/IP/MTU/路由/ACL；准备 DNS、NTP、内部 CA、代理和私有仓库地址。
5. 带外管理口使用独立管理网，修改默认口令，启用 RBAC、审计和可信证书，限制来源地址。

### 2.2 通电与硬件验证

- 在 BMC/UEFI 中核对 BIOS、BMC、CPLD、GPU/网卡/SSD 固件及硬件清单，导出事件日志；仅升级到整机厂商认证基线，禁止无变更单批量刷写。
- 检查 CPU、内存、PCIe 链路宽度/速率、NUMA 拓扑、GPU 间互联、磁盘 SMART、网卡链路和冗余电源状态。
- 执行内存、CPU、GPU/加速卡、NVMe 和网络压力测试；多机额外验证 RDMA/RoCE 或 InfiniBand 连通、无损网络配置和端到端带宽。
- 烧机时持续记录温度、功耗、降频、风扇、ECC、PCIe/AER、掉盘/掉卡及链路重传。时长按交付标准约定，生产设备建议覆盖峰值负载和冷热循环。

**验收门槛：**资产与 BOM 一致；无不可纠正 ECC、介质错误和硬件告警；设备不掉线、不异常降频；磁盘、网络及卡间通信达到方案基线；A/B 路断电测试不影响设计范围内负载。原始日志、固件版本和测试结果归档。

## 3. Linux、驱动与固件基线

1. 选择厂商支持的企业 Linux 发行版与内核，不将“能够安装”视为“生产受支持”。最小化安装，固定软件源快照。
2. 配置主机名、静态地址、DNS、NTP/PTP、时区、内部 CA、审计、日志转发、磁盘挂载和交换分区策略。
3. 根据推理引擎建议设置文件句柄、锁页内存、共享内存及 NUMA；所有内核参数必须进入配置管理并保留变更理由。
4. 启用 Secure Boot 时，确认驱动模块签名链；禁止为图方便长期关闭安全机制。
5. 驱动安装后，先做宿主机设备枚举、健康状态、算子和卡间通信测试，再安装容器设备运行时。

兼容矩阵至少包含：`服务器/主板固件—OS—内核—IOMMU—加速卡固件—驱动—计算运行时—通信库—容器运行时—设备插件—推理引擎—模型格式/量化方式`。任何一层变更都应触发相关回归测试。

## 4. 加速卡兼容性分支

| 路线 | 必查软件栈 | 核验重点 | 常见风险 |
|---|---|---|---|
| NVIDIA | 数据中心驱动、CUDA、NCCL、Container Toolkit、K8s Device Plugin/GPU Operator | 驱动与 CUDA 最低版本；GPU 架构与引擎算子；NVLink/NVSwitch；MIG；GPUDirect/RDMA | 驱动/容器 CUDA 不匹配、NCCL 拓扑或网络配置错误、量化内核不支持旧架构 |
| AMD | ROCm、HIP、MIOpen、RCCL、容器与 K8s 设备插件 | GPU 型号是否在目标 ROCm/OS 官方支持表；HIP 算子覆盖；Infinity Fabric/RDMA；引擎 ROCm 后端 | 宣称兼容但算子缺失、镜像仅支持特定发行版/内核、量化实现差异 |
| 国产卡 | 厂商驱动/固件、计算与通信库、容器工具、设备插件、适配版引擎 | 整机认证清单；OS/内核与信创发行版；框架和模型算子白名单；多卡集合通信；许可证与维保 | 版本绑定强、社区引擎特性滞后、模型转换产生精度差异、离线补丁获取周期长 |

兼容性不得仅凭营销材料判断。实施时应完成：

1. 查阅芯片厂商、服务器 OEM、OS 和推理引擎四方官方支持矩阵并留存链接/截图与核验日期。
2. 使用目标模型、目标精度、目标上下文执行单卡冒烟测试；验证长上下文、流式输出和关键算子。
3. 扩展至单机多卡，测试 P2P、集合通信、张量并行和持续负载；再扩展多机。
4. 对同一固定评测集比较 CPU/参考实现与加速卡结果，记录质量偏差、首 Token 时延、吞吐、显存及功耗。
5. 固化“已验证组合”；未通过组合只能进入实验环境。国产卡若需厂商定制插件，应明确源码/二进制交付、升级 SLA 和退出方案。

## 5. 容器与编排选型

### 5.1 容器层

优先采用组织标准的 containerd 或 Docker，并安装对应厂商设备运行时。镜像必须使用固定 digest，不得以浮动 `latest` 进入生产。基础镜像、驱动用户态库、推理引擎和 Python 依赖分别记录 SBOM、许可证、漏洞扫描结果和构建来源。

验证顺序：宿主机可见设备 → 最小设备容器可见设备 → 容器内算子测试 → 多卡通信 → 推理镜像加载模型。容器内失败时退回上一层，禁止同时更换驱动、镜像和模型定位问题。

### 5.2 编排决策

- **PoC/单机：**systemd + Compose/Podman Compose；组件少、恢复简单，但需自行实现健康检查、滚动发布和资源隔离。
- **少量节点：**轻量 K8s（如经客户批准的 k3s/RKE2）或既有容器平台；适用于有限节点且客户缺少完整 K8s 运维能力的场景。
- **多租户/高可用集群：**标准 Kubernetes；配置设备插件/Operator、节点标签与污点、配额、优先级、拓扑感知、PodDisruptionBudget 和反亲和。

K8s 验收包括：每张卡可分配且不重复分配；失败 Pod 释放资源；节点维护可排空；模型卷权限正确；调度尊重卡型、显存/切分能力和互联拓扑；控制面故障不影响已运行推理；滚动或蓝绿发布可回退。不要假设原生 GPU 数量调度能表达显存、拓扑和模型驻留需求，必要时采用经验证的扩展调度器。

## 6. 推理引擎、模型仓库与 API 平面

### 6.0 分层主选、备选与放行依据

“主选”是项目默认候选，不代表所有硬件通用；“备选”只有完成同口径验证后才能接管。国产加速卡若不支持通用组件，以厂商正式支持且通过目标模型验证的等价组件替换。

| 层 | 通用主选候选 | 备选候选 | 放行依据 |
|---|---|---|---|
| OS | 整机与加速卡共同支持的企业 Linux | 客户信创 OS 或另一受支持企业发行版 | OEM、卡厂商、内核与安全基线共同通过 |
| 容器 | containerd + 厂商设备运行时 | Docker Engine（轻量单机）或 CRI-O | 容器内设备、隔离、重启、日志和升级回退实测 |
| 编排 | 单机用 systemd/Compose；多租户/多节点用 Kubernetes | 经验证的轻量 Kubernetes 或客户既有平台 | 团队运维能力、故障域、调度、滚动升级和资源释放 |
| 推理 | vLLM/SGLang 等开放引擎中择一 | TGI、TensorRT-LLM 或卡厂商适配引擎 | 目标模型/精度/量化/API/性能/长稳/HA 同口径压测 |
| 模型仓库 | 客户对象存储/制品库 + 不可变摘要 | 受控共享存储或企业模型 Hub | 权限、哈希/签名、版本、血缘、备份恢复和离线导入 |
| API 网关 | 客户既有企业网关 | Envoy、Kong、APISIX、Nginx 等经批准方案 | TLS/mTLS、OIDC、RBAC、Token 限流、流式响应、审计和 HA |
| 监控 | Prometheus 生态 + Grafana + 厂商 GPU Exporter | 客户既有可观测平台 | GPU 到业务 SLI 关联、告警路由、留存、离线运行和恢复 |
| RAG | 客户支持的关系/搜索/向量存储组合 | 独立向量库或混合检索引擎 | ACL 前置过滤、混合召回、备份恢复、扩缩和删除传播 |

兼容性验证使用同一张证据表：`组件及准确版本—官方支持链接—镜像 digest/SHA-256—硬件/OS—目标模型—测试项—结果—限制—回退版本—核验人/日期`。主备方案必须使用同一评测集、请求分布、SLA 和安全用例，禁止用不同口径证明“可替换”。

### 6.1 推理引擎

选型按模型架构与量化支持、加速卡后端、连续批处理、Paged KV Cache、张量/流水线并行、结构化输出、流式接口、监控和商业支持评估。开源通用场景可评估 vLLM、TGI、SGLang；NVIDIA 深度优化可评估 TensorRT-LLM；其他加速卡优先使用厂商明确支持且通过目标模型验证的引擎。主选与备选均需保留模型转换和 API 兼容性验证结果。

发布流程：许可证确认 → 权重哈希校验 → 注册模型版本 → 必要的格式转换/量化 → 离线评测 → 引擎配置 → 预热 → 健康检查 → 小流量灰度 → 性能复测 → 全量。回滚必须同时恢复模型、引擎镜像、启动参数和网关路由。

### 6.2 模型仓库

模型仓库保存原始权重、转换产物、Tokenizer、配置、许可证、评测报告及血缘。生产版本应不可变并以语义版本或内容摘要引用；上传、审批、发布、废弃分权。大文件启用分片/断点续传、静态加密、访问审计和备份恢复演练。禁止运行来源不明的自定义代码；确需 `trust_remote_code` 时先代码审查并在受限环境执行。

### 6.3 网关、鉴权与限流

推理服务仅暴露给内部 API 网关。网关统一提供 TLS/mTLS、SSO/OIDC 或服务身份、RBAC、租户隔离、模型级授权、请求大小与上下文限制、超时/重试、熔断和审计。密钥存入客户认可的密钥管理系统，不写入镜像、脚本和日志。

限流至少同时考虑 `请求数/分钟、并发请求、输入 Token、输出 Token、总 Token、队列长度`，并区分租户、应用、用户和模型。流式响应不得因网关缓冲失效；重试仅用于明确可重试且幂等的阶段，避免重复生成导致算力放大。敏感日志默认不记录提示词和模型完整输出，确需留存须脱敏、授权并设置保留期。

## 7. 联网、半离线与完全隔离链路

### 7.1 联网环境

1. 通过企业软件源、镜像代理和模型代理获取制品，禁止生产节点任意访问互联网。
2. 锁定包版本和镜像 digest，保存依赖清单、SBOM、许可证及哈希/签名。
3. 扫描漏洞与恶意文件，经审批后同步到私有软件源、镜像仓库和模型仓库。
4. 从私有仓库执行可重复安装；禁用运行时自动下载模型或依赖。

### 7.2 半离线环境

使用受控下载区/跳板机，业务区仅访问代理或内部仓库。链路为：需求清单审批 → 下载区拉取 → 哈希/签名与许可证检查 → 恶意文件扫描 → 同步到中转仓 → 业务区复核 → 导入私库 → 安装。代理日志和制品流转单需关联变更单；禁止把代理配置和凭据烘焙进生产镜像。

### 7.3 完全隔离环境

在同架构、同 OS 的联网制品机生成离线包，至少包含：OS/内核包、固件与驱动、容器二进制及镜像、Helm/部署清单、推理引擎、模型与 Tokenizer、校验清单、SBOM、许可证、安装/回滚脚本和已知问题。经双人复核、签名、恶意文件扫描后，通过客户批准的加密介质和物理交接流程导入。隔离区先在检疫机复验哈希/签名，再导入内部 RPM/DEB、OCI 和模型仓库；在无外网、空缓存环境完成一次重装演练，证明无隐式下载。

## 8. 升级与回滚

升级顺序遵循依赖关系，但不得一次跨多层变更：先在镜像环境验证兼容矩阵和数据/模型质量，再灰度至非关键副本。驱动或固件升级通常需要节点排空和重启，应保持旧节点承载流量；模型/引擎使用蓝绿或金丝雀。升级包沿用对应联网级别的供应链流程。

每次变更必须记录前后版本、影响面、备份、验证项、回滚触发阈值和负责人。以下任一情况立即回滚：设备不可见或通信错误增加；质量基线超阈值；P95/P99 时延、错误率或吞吐恶化超过批准范围；显存泄漏、持续降频或节点不稳定。固件降级可能受厂商限制，实施前必须确认可逆性；不可逆升级应先在备用节点验证并获得客户书面批准。

## 9. 最终交付检查表

- [ ] 资产、网络、供电、散热、BMC 与固件台账完整

- [ ] 加速栈兼容矩阵含官方来源、核验日期和实测结果
- [ ] 单卡、单机多卡、多机通信及烧机无阻断问题
- [ ] 容器镜像以 digest 固定，SBOM、漏洞和许可证审查完成
- [ ] 编排调度、资源释放、节点维护和发布回滚验证通过
- [ ] 模型权重、转换产物、评测和许可证具备完整血缘
- [ ] 网关 TLS、身份、RBAC、配额、限流、审计与脱敏生效
- [ ] 当前联网级别下可从私有制品完成全新安装
- [ ] 升级、备份恢复、回滚及故障件处理流程已演练
- [ ] 所有报告、配置、哈希、签字与责任边界纳入交付档案
