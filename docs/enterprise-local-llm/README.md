# 企业本地大模型部署实操手册

> 核验日期：**2026-08-27**  
> 适用对象：为企业客户提供本地化大模型售前、PoC、实施、验收和维保服务的项目经理、解决方案架构师、平台/算法/安全/运维工程师。  
> 核心方法：**先判断、再分支、后执行；先基线、再增强；先单点验证、再扩大故障域。**

## 1. 使用边界

本手册是交付方法、检查表和模板，不是采购承诺、法律意见或任何厂商产品的兼容性担保。

- 不替客户采购硬件、操作生产网络或接触未经授权的数据。
- 不承诺某个模型在所有业务上达到固定效果；效果必须用客户确认的评测集实测。
- 不提供模型权重、商业许可证、破解方法或规避许可、监管和数据合规要求的方案。
- 型号、驱动、软件版本、许可条款、价格与交期均会变化，采购和实施前必须重新核验。
- 行业监管、数据分类分级、跨境、模型/数据许可和密码应用结论由客户法务、合规、安全及数据责任人确认。

## 3. 十分钟首次判断

按以下顺序回答；任何红线项未关闭，都不要直接给型号和报价。

1. **业务是否值得做**：现状基线、目标指标、失败代价和业务 Owner 是否明确？
2. **数据能否使用**：权属、密级、地域、保留期、删除链路和真实数据准入是否已批准？
3. **模型能否使用**：目标用途是否允许商用、本地托管、量化、微调及向客户提供服务？
4. **环境能否部署**：联网、半离线还是完全隔离？是否有信创、指定厂商或指定 OS 的硬约束？
5. **SLA 是否需要 HA**：允许计划停机吗？单机故障是否可接受？RTO/RPO 是多少？
6. **质量问题属于哪类**：
   - 知识缺失或更新快：优先 RAG；
   - 行为、格式或风格不稳定：提示基线不足后再评估 LoRA；
   - 质量已达标但资源不足：量化、调度、批处理或扩容；
   - 基座能力确实不足且长期投入充足：最后才评估持续预训练/全量训练。
7. **资源是否可复算**：参数量、精度、KV Cache、上下文、并发、批处理和余量是否进入同一容量表？
8. **机房是否承载得住**：机柜、A/B 路、PDU、UPS、散热、网络、带外管理及备件是否就绪？
9. **能否回退**：模型、镜像、驱动、配置、索引和数据变更是否都有明确回退点？
10. **谁来签字和接班**：需求、设计、数据、安全、验收、上线、维保和退场责任是否明确？

## 4. 端到端主线

```text
商机筛选
  → 需求与合规分流
  → PoC（价值、效果、容量）
  → 生产方案与容量冻结
  → 采购及机房就绪
  → 基础系统和加速栈
  → 模型/RAG/应用联调
  → 功能、效果、性能、稳定、安全和恢复验收
  → 灰度上线
  → 运维、巡检、变更、扩容和事故复盘
  → 退场、账号撤销和数据处置
```

每一阶段均在第一分册中按统一执行卡描述：**前置条件、输入、步骤、产物、验收、回退、责任角色**。不得只写“安装完成”或“测试通过”。

## 6. 稳定方法论与时效信息分离

### 6.1 稳定层

以下内容可长期复用，但项目参数仍须书面确认：

- 决策树、阶段门禁、RACI、停止条件；
- 容量公式和“理论值—实测值—规划值”校准方法；
- 先单卡、再单机多卡、最后多机的验证顺序；
- 制品不可变、哈希/签名、SBOM、最小权限、审计和回退原则；
- 质量、性能、稳定、HA、安全、恢复的验收分类；
- SLI/SLO、错误预算、分级告警、值班、变更与复盘方法。

### 6.2 时效层

以下内容不得从旧项目复制：

- GPU/加速卡型号、显存、功耗、互联和整机支持状态；
- BIOS/BMC/固件、OS、内核、驱动、CUDA/ROCm/国产计算栈版本组合；
- 推理引擎、容器、Kubernetes 设备插件和量化算子的支持范围；
- 模型版本、上下文、Tokenizer、模型卡、许可证及商用条款；
- 漏洞、补丁、生命周期、软件许可、硬件价格、交期和维保报价。

每个时效项必须登记：`核验日期、准确版本/料号、官方 URL、页面版本或发布日期、核验人、验证环境、实测结果、失效/复核日期`。

├── 02-architecture/    # HLD/LLD、容量、BOM、网络、机柜与兼容矩阵
├── 03-artifacts/       # 制品清单、SBOM、哈希、签名和许可证
├── 04-install/         # 安装步骤、配置基线、自动化、回退包
├── 05-test-evidence/   # 功能、效果、性能、长稳、HA、安全、恢复证据
├── 06-operations/      # 监控、SLO、告警、SOP、巡检和事故复盘
├── 07-handover/        # 培训、账号、资产、验收签字和维保边界
└── 08-retirement/      # 退场、撤权、导出、擦除和销毁证明

生产密钥、令牌、真实业务数据和模型权重不得放入普通文档库或 Git；文档仅保存受控系统中的引用和内容摘要。

## 8. 最终放行原则

只有同时满足以下条件才可建议生产上线：

- 需求、数据、许可、设计和风险均有授权人书面结论；
- 目标模型、目标精度、真实请求分布和候选硬件完成实测校准；
- 功能、质量、性能、长稳、HA、安全和恢复验收达到冻结阈值；
- 监控、告警、值班、备份、回退、容量余量和故障接管均已演练；
- 客户团队完成培训并能独立执行启停、告警确认、恢复和报障；
- 遗留风险均有责任人、补偿控制、失效日期和风险接受签字。

未满足时的正确动作是**缩范围、降级、延后或停止**，而不是隐藏假设继续上线。
