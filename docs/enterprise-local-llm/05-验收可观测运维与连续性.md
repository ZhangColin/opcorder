# 生产验收与持续运维

> 本章所有阈值均须在项目启动时由甲乙双方书面确认；未填写的指标不得视为默认承诺。行业合规结论由客户法务、合规及数据责任人最终确认。

## 1. 生产验收总则

### 1.1 准入条件

- 架构、BOM、模型许可证、数据分级、网络边界和版本矩阵已审批。
- 生产配置冻结，监控、告警、审计、备份和回滚路径已启用。
- 测试数据已脱敏并获授权；基准集、压测脚本、随机种子和判定阈值已锁定。
- 已明确测试窗口、影响范围、停止条件、故障联系人和恢复责任人。

### 1.2 验收流程

1. **先判断**：确认单机/集群、RAG/非 RAG、联网/隔离及适用测试项。
2. **再分支**：按功能效果、性能、稳定性、HA、恢复、安全逐项执行。
3. **后执行**：记录原始数据、环境指纹、时间戳和操作者，不只保留汇总图。
4. 缺陷按“阻断/严重/一般/观察项”登记；阻断项不得带病上线。
5. 调优后必须使用同一基准集复测，并注明所有参数变化。
6. 由业务、技术、安全和运维共同评审，形成签字结论。

### 1.3 验收矩阵

| 类别 | 最低覆盖 | 证据 | 判定 |
|---|---|---|---|
| 功能 | 鉴权、限流、流式/非流式、取消、超时、上下文、批处理、模型路由 | API 记录、截图、测试报告 | 用例通过率 ≥ `__%`，阻断缺陷为 0 |
| 效果 | 任务成功率、拒答、幻觉、敏感内容；RAG 另测检索、引用、权限过滤 | 固定版本评测集及逐题结果 | 指标达到业务基线 `__`，无越权样例 |
| 性能 | TTFT、TPOT、端到端时延、输出吞吐、并发、排队 | 压测原始结果和资源曲线 | 达到第 2 节阈值 |
| 稳定性 | 长稳、峰值、长上下文、异常输入、资源泄漏 | 连续运行记录 | 达到第 3 节阈值 |
| HA | 实例、节点、网络、存储、调度组件故障 | 故障注入与切换时间线 | RTO/RPO 和成功率达标 |
| 恢复 | 配置、元数据、向量库、模型注册信息恢复 | 恢复演练记录 | 校验一致且在 RTO/RPO 内 |
| 安全 | 身份、权限、加密、供应链、注入、外泄、审计 | 扫描/渗透/整改报告 | 高危、严重风险为 0 |
| 容量 | GPU/CPU/RAM/磁盘/网络/功耗余量 | 峰值监控快照 | 余量达到约定 `__%` |

### 1.4 停止与回退

出现生产数据污染、权限越界、持续错误率超过 `__%`、温度/功耗越限、不可逆写入、审计失效或影响其他生产系统时立即停止。恢复流量、配置和数据至测试前检查点；未完成根因分析和重新审批不得续测。

## 2. 性能测试

### 2.1 指标口径

- **TTFT**：网关收到请求至客户端收到首 Token；报告 P50/P95/P99。
- **TPOT**：首 Token 后相邻输出 Token 平均耗时；报告 P50/P95/P99。
- **端到端时延**：请求进入网关至最后一个 Token 返回。
- **吞吐**：成功输出 Token/s、成功请求/min；同时报告输入/输出 Token 数。
- **并发**：系统内同时处理请求数，不以压测线程数替代。
- **成功率**：符合协议且完整结束的请求数/总请求数；客户端取消单列。
- RAG 另报检索时延、重排时延、首段召回率、引用正确率和越权率。

### 2.2 场景设计

| 场景 | 输入/输出长度 | 负载模型 | 目的 |
|---|---:|---|---|
| 基线 | `__/__ Token` | 单并发，预热后 30 次 | 排除排队影响 |
| 常规 | 按生产分布 | 阶梯升压 | 找到目标并发下 SLO |
| 峰值 | P95 长度 | 峰值 `__` 分钟 | 验证余量和限流 |
| 长上下文 | `__` Token | 低到中并发 | 验证 KV Cache、OOM 与质量 |
| 突发 | `__→__ RPS` | 瞬时升压 | 验证排队、熔断和恢复 |
| 混合租户 | 各租户真实配比 | 带配额和优先级 | 验证公平性和隔离 |

### 2.3 执行步骤

1. 记录模型/量化、引擎参数、GPU 型号与数量、驱动、固件、镜像摘要、拓扑和环境温度。
2. 使用固定请求集；固定采样参数，输入与输出长度分桶，禁止只报均值。
3. 预热至权重加载、图编译和缓存稳定，再采集基线。
4. 按并发 `1→2→4→…→目标→峰值` 阶梯升压，每档持续不少于 `__` 分钟。
5. 同步采集应用、队列、GPU、CPU、内存、磁盘和网络指标。
6. 找出拐点：吞吐不再线性增长，且 P95 时延或错误率快速上升。
7. 一次只修改一个主要变量；复测并保留前后对照。

## 3. 稳定性、高可用与备份恢复

### 3.1 稳定性测试

- **长稳**：按日常负载连续 `__` 小时，期间错误率 ≤ `__%`，无未恢复 OOM、死锁、句柄/内存持续增长。
- **峰值保持**：按峰值负载持续 `__` 分钟，限流行为符合约定，恢复至基线不超过 `__` 分钟。
- **耐久检查**：前后对比显存、主存、磁盘、连接数、线程、队列深度和 P95 时延；趋势斜率异常必须解释。
- **异常输入**：超长、空输入、非法编码、大附件、断流、重复请求和客户端取消均不得拖垮服务。

### 3.2 HA 故障注入

| 故障 | 预期行为 | 必留证据 |
|---|---|---|
| 单推理实例退出 | 健康检查摘除，流量转移；在途请求按约定重试 | 摘除/恢复时间、失败请求数 |
| 单计算节点断电/断网 | 不再调度；冗余容量承接流量 | 节点事件、容量曲线、RTO |
| 网关实例故障 | VIP/DNS/负载均衡切换，无单点 | 切换时间和客户端观测 |
| 调度/控制面故障 | 已运行服务不受影响或按设计降级 | 选主及恢复记录 |
| 存储路径中断 | 只读/熔断，不产生静默损坏 | 校验结果、恢复步骤 |
| 机房/故障域失效 | 切换至灾备或执行停服预案 | RTO、RPO、业务确认 |

故障注入前须确认爆炸半径、回退命令、带外访问和业务批准。若架构本身无冗余，应明确记录“接受单点风险”，不得标记为 HA 通过。

### 3.3 备份策略

| 对象 | 方法 | 频率/保留 | 加密与权限 | RPO | 恢复优先级 |
|---|---|---|---|---:|---:|
| 配置、密钥引用、策略 | 版本化导出；密钥材料单独托管 | `__` | `__` | `__` | 1 |
| 模型清单/注册元数据 | 数据库备份 + 权重摘要 | `__` | `__` | `__` | 2 |
| RAG 原文、索引、向量库 | 原文为权威源；索引快照或可重建 | `__` | `__` | `__` | 2 |
| 业务会话/反馈 | 按数据分级备份或明确不备份 | `__` | `__` | `__` | 3 |
| 审计日志 | WORM/集中存储 | `__` | `__` | `__` | 1 |

遵循 `3-2-1` 原则；完全隔离环境使用经审批、编号、查毒、加密的离线介质。备份成功不等于可恢复，至少每 `__` 月实施一次恢复演练。

### 3.4 恢复演练

1. 选择独立恢复环境，冻结并记录恢复点。
2. 校验备份摘要、签名、可读性和解密授权。
3. 按“基础设施 → 身份与密钥引用 → 配置 → 元数据 → 数据/索引 → 服务”恢复。
4. 校验行数/对象数/哈希、权限边界、模型版本和关键业务抽样。
5. 记录实际 RPO、RTO、人工步骤和失败点；清理演练数据。

## 4. 安全测试

安全测试必须获得书面授权，并限定时间、源地址、账号、数据和禁止动作。

| 域 | 测试重点 | 通过标准 |
|---|---|---|
| 身份与权限 | SSO/MFA、RBAC、服务账号、跨租户访问、离职账号 | 最小权限生效，无水平/垂直越权 |
| 网络 | 分区、默认拒绝、管理面、出站控制、TLS | 未授权路径不可达；弱协议禁用 |
| 数据 | 传输/静态加密、脱敏、删除、导出、日志泄漏 | 敏感数据不明文暴露，删除可验证 |
| 密钥 | 存储、轮换、吊销、代码/镜像泄漏扫描 | 无硬编码密钥；轮换不致服务失控 |
| 供应链 | SBOM、镜像/软件包/权重签名与哈希、许可证、漏洞 | 来源可追溯；严重/高危漏洞为 0 或有正式豁免 |
| API | 鉴权绕过、重放、注入、限流、超长请求、错误信息 | 拒绝行为符合策略，不泄漏内部信息 |
| LLM | 提示注入、越狱、系统提示窃取、工具滥用、数据外泄 | 高风险用例被拦截或安全降级 |
| RAG | 文档投毒、权限过滤、跨租户检索、恶意附件 | 无越权召回；摄取链有扫描和审批 |
| 审计 | 登录、授权、配置、模型、数据导出、管理员操作 | 主体、时间、对象、结果完整且防篡改 |

风险记录须包含：编号、资产、复现条件、证据、CVSS/业务影响、责任人、修复期限、复测结论和风险接受人。不得用“网络隔离”替代漏洞治理；无法修复项必须有补偿控制、到期日和管理层签字。

## 5. 可观测性

### 5.1 分层指标

- **业务/SLO**：请求量、成功率、P95/P99 时延、可用性、租户配额、拒绝/降级率。
- **模型服务**：TTFT、TPOT、输入/输出 Token、批大小、队列深度、缓存命中、OOM、加载与预热时长。
- **质量**：任务成功率、人工反馈、拒答/幻觉趋势；RAG 的召回、引用、无答案率、权限拦截。质量指标不得直接写入敏感原文。
- **GPU/加速卡**：利用率、显存、温度、功耗、时钟、节流、ECC/Xid 或厂商等价错误、互联带宽。
- **主机/网络/存储**：CPU、内存、磁盘容量与时延、inode、丢包、重传、吞吐、NTP 偏差。
- **容器/集群**：重启、Pending、驱逐、探针、调度失败、控制面状态、证书有效期。
- **安全/审计**：认证失败、权限拒绝、异常导出、策略修改、漏洞和签名校验失败。
- **成本/容量**：GPU 小时、Token/租户、闲置率、容量余量及增长趋势。

### 5.2 日志与追踪规范

统一 `timestamp、request_id、trace_id、tenant_id（脱敏）、model_version、route、status、latency、token_count、error_code`。禁止记录口令、密钥、完整系统提示和未经批准的用户原文。指标、日志、追踪时间统一；监控链路自身也须监控采集延迟、丢数和存储余量。

仪表盘至少包含：管理总览、SLO、推理性能、GPU/节点、集群容量、RAG 质量、安全审计和备份恢复。

### 8.1 值班交接

|---|---|---|

## 9. 变更与升级

### 9.1 变更流程

1. 提交变更单：目的、范围、版本、依赖、风险、爆炸半径、验证、回滚和窗口。
2. 按标准/一般/重大/紧急分类；重大变更需业务、运维、安全共同审批。
3. 在等价环境验证兼容矩阵：固件—驱动—运行时—容器—引擎—模型—插件。
4. 备份并验证回滚材料；记录配置和制品摘要。
5. 采用金丝雀 `__%→__%→__%` 或蓝绿发布，每阶段观察 `__` 分钟。
6. 检查 SLO、质量、安全、容量和业务指标后扩大流量。
7. 完成后更新 CMDB、架构图、Runbook、SBOM 和版本台账。

### 9.2 自动停止条件

错误率增加 `__`、P95/TTFT 恶化 `__%`、质量低于基线、出现 OOM/ECC/数据不一致、审计缺失或安全策略失效时立即停止并回滚。回滚也失败则转事故流程。

离线环境的升级介质须记录来源、审批单、哈希/签名、恶意代码扫描结果、导入/销毁人和时间；禁止现场临时联网拉取依赖。

## 10. 事故响应与复盘

### 10.1 响应流程

1. **发现与定级**：确认用户影响、数据/安全影响、范围和开始时间。
2. **建立指挥**：指定事故指挥官、技术负责人、沟通人、记录员；统一时间线。
3. **止损优先**：限流、隔离、摘除、回滚或安全降级；先恢复服务，再做完整根因分析。
4. **保全证据**：保存日志、追踪、配置、镜像摘要和审计记录；涉及安全事件时遵循监管和法务通知流程。
5. **恢复验证**：用业务探针、数据一致性和 SLO 验证，不以“进程已启动”作为恢复。
6. **沟通**：按约定频率向利益相关方更新已知事实、影响、措施和下一次更新时间，不推测、不甩责。
