# 模型上线、RAG、微调训练与安全

## 模型上线顺序与故障树

### 上线原则

采用“先基线、后增强；先单实例、后集群；先影子、后灰度、再全量”。任何阶段未满足退出标准，不得带病进入下一阶段。

| 顺序 | 动作 | 进入条件 | 通过标准 | 失败回退 |
|---|---|---|---|---|
| 1 | 许可与制品准入 | 用途、地域、再分发及商用条款已审查 | 权重、配置、Tokenizer 哈希一致；扫描无高危项 | 隔离制品，禁止加载 |
| 2 | 离线功能基线 | 单卡/单机可加载 | 固定测试集输出可复现，无崩溃/OOM | 回退原始格式、精度及已验证驱动 |
| 3 | 性能基线 | 功能基线通过 | TTFT、TPOT、吞吐、显存满足方案值并保留余量 | 降低上下文/并发，调整批处理或并行策略 |
| 4 | 安全联调 | 网关、IAM、审计、密钥系统就绪 | 越权、注入、泄露测试通过 | 关闭外部入口，仅保留隔离测试 |
| 5 | 影子流量 | 不向用户返回结果 | 错误率、质量、资源曲线无回归 | 停止镜像流量 |
| 6 | 1%–5% 金丝雀 | 可按租户/请求回切 | 连续观察窗内 SLO 达标，无 P1/P2 事件 | 网关秒级切回旧版本 |
| 7 | 分批扩量 | 每批均有审批和观测窗 | 5%→25%→50%→100% 均达标 | 回退上一稳定比例 |
| 8 | 全量与固化 | 回滚演练成功 | 版本、配置、评测、审批、操作记录归档 | 保留上一版本与兼容数据快照 |

### 故障树（先定位故障域）

```text
请求失败/体验下降
├─ 无法访问
│  ├─ DNS/LB/网关异常 → 检查解析、证书、后端健康、限流
│  ├─ 鉴权失败 → 检查时钟、令牌签发、RBAC、密钥轮换
│  └─ 服务无副本 → 检查调度、镜像拉取、配额、节点状态
├─ 5xx/进程退出
│  ├─ OOM → 区分权重/KV Cache/碎片；降并发和上下文后复测
│  ├─ 驱动或算子不兼容 → 对照版本矩阵，回退驱动/镜像
│  └─ 权重损坏 → 校验哈希，从可信仓库重新导入
├─ 延迟或吞吐不达标
│  ├─ 排队过长 → 检查限流、批处理、扩副本
│  ├─ GPU 利用率低 → 检查 CPU、存储、网络、Tokenizer 瓶颈
│  └─ 跨卡通信慢 → 检查拓扑、RDMA/NCCL、错误包及链路降速
├─ 输出质量下降
│  ├─ 模型/量化变更 → 与黄金集及旧版本 A/B
│  ├─ 模板/Tokenizer 错配 → 恢复配套版本
│  └─ RAG 异常 → 检查数据版本、权限过滤、召回、重排、引用
└─ 安全事件
   ├─ 提示注入/越权工具调用 → 熔断工具与外部检索
   ├─ 敏感信息泄露 → 停止响应、吊销凭据、保全脱敏证据
   └─ 制品疑似污染 → 隔离节点和制品，切回可信版本
```

**处置顺序：**保护人员与数据 → 熔断入口/危险工具 → 固定时间线和证据 → 切回已知稳定版本 → 恢复最小服务 → 根因分析。禁止在生产节点临时改包后继续运行。

## RAG 进入、实施与退出条件

### 何时进入 RAG

满足以下全部条件方可进入：

- 问题主要来自“知识缺失、知识更新快、需引用依据”，而非基础推理能力不足；
- 文档来源、责任人、授权范围和保留期限明确；
- 可构建包含标准答案、可接受引用和无答案样本的评测集；
- 访问控制能在检索前执行，不能仅靠提示词要求模型保密；
- 原模型直接推理基线已记录，RAG 的收益可被量化。

不应进入：数据来源违法或权属不明；文档无法按用户权限切分；目标是灌输稳定行为/格式而非补充事实；没有评测集便直接全量建库。

### 实施链路

1. **数据登记：**记录来源、所有者、密级、授权、更新时间、删除要求和文档 ID。
2. **解析清洗：**去页眉页脚、重复、乱码和隐藏指令；保留标题层级、页码、时间及 ACL 元数据。
3. **切分：**按语义边界切分并设置重叠；表格、代码、扫描件分别制定策略，禁止只按固定字符盲切。
4. **索引：**Embedding、切分器、解析器及向量库均版本化；原文与向量使用同一文档 ID。
5. **检索：**先 ACL 过滤，再混合召回，随后重排；设置最低相关度和无答案路径。
6. **生成：**明确“资料不足则拒答”，输出文档名、版本、页码/段落；外部内容按不可信输入处理。
7. **评测：**至少覆盖召回率@K、MRR/NDCG、答案正确率、引用准确率、忠实度、拒答率、越权率、延迟和成本。
8. **发布：**按知识库版本灰度；保留旧索引、原文快照及可逆迁移脚本。

### RAG 退出/回退条件

出现任一项立即停止扩量；涉及越权或泄露时立即熔断：

- 未授权文档可被检索、引用或侧信道推断；
- 引用不存在、错配，或忠实度低于批准阈值；
- 数据删除后，原文、缓存、索引、备份未按策略联动删除；
- P95 延迟、错误率或资源成本连续超过 SLO；
- 新索引相对基线显著回归且无法在观察窗内修复。

回退顺序：冻结增量同步 → 网关切换旧索引 → 清理查询/生成缓存 → 验证权限与删除传播 → 复测黄金集后再申请上线。

## LoRA、QLoRA 与全量训练的进入/退出条件

| 路线 | 适合解决 | 进入条件 | 不应进入 |
|---|---|---|---|
| LoRA | 风格、格式、领域行为、工具调用模式 | 基线/RAG/提示工程仍不足；有高质量监督数据和可量化指标；资源预算明确 | 目标仅为更新事实；数据少且噪声高 |
| QLoRA | 显存受限下验证 LoRA 收益 | LoRA 条件均满足；量化算子与卡型验证通过；接受潜在质量折损 | 精度极敏感且无逐层对比评测 |
| 全量训练/持续预训练 | 大幅改变领域表征、语言能力或基础能力 | LoRA 收益已证实但触顶；数据规模、版权、算力、分布式团队及恢复预算完备 | 为展示而训练；无干净语料、无消融实验、无训练恢复演练 |

### 明确何时不做微调或训练

出现以下任一情况，不启动微调、持续预训练或全量训练；先回到需求、数据与轻量方案：

- **问题属于知识更新或事实可追溯：**优先使用 RAG、搜索或业务数据库，不用训练“记住”频繁变化的事实。
- **提示词、结构化输出、规则或工具编排已能达标：**不为边际收益增加训练和长期维护成本。
- **没有冻结的基线和独立测试集：**无法证明训练收益，也无法识别通用能力或安全回归。
- **数据不足、噪声高或代表性不明：**少量错误样本可能放大偏差；先治理、补采和人工复核数据。
- **数据权利或模型许可不清：**训练权、衍生权、商用权、输出使用权任一项未确认即停止。
- **数据含个人信息、商业秘密或受监管数据但无合法基础：**未完成目的限定、最小化、脱敏、审批和删除机制前不得训练。
- **测试集污染或训练/测试近重复无法排除：**不得以失真的离线指标作为立项依据。
- **没有算力预算、检查点恢复、实验追踪和回滚能力：**不得启动长周期或分布式训练。
- **基础模型能力明显不匹配任务：**应重新选型，而不是用微调强行弥补架构、语言或模态缺陷。
- **安全评测和上线责任人缺位：**不得将实验权重接入生产或真实业务数据。

全量训练是最后分支，而非默认升级路径。只有轻量方法经过受控对照实验已证明有效但达到能力上限，并且新增收益覆盖数据治理、算力、评测、安全与长期运维成本时，才进入立项评审。

### 升级决策

```text
原模型是否达标？—是→停止增强
否→是否因知识缺失且需引用？—是→RAG
否→提示模板/工具编排能否解决？—是→保持轻量方案
否→行为或领域适配是否有稳定监督数据？—是→先 QLoRA/LoRA
LoRA 是否经对照实验证明收益且仍触顶？—否→停止升级
是→全量训练立项评审
```

### 训练控制点

- 数据集按来源、许可、密级、去重规则及 train/validation/test 划分登记；测试集与训练集做近重复检测。
- 固定随机种子、基础模型哈希、代码提交、容器摘要、超参数、数据版本和硬件拓扑。
- 每个里程碑保存可恢复检查点；至少演练一次中断续训。
- 同时评估目标任务、通用能力、安全集、记忆泄露、偏见、长上下文和性能成本。
- 适配器与基础模型绑定登记，禁止混用 Tokenizer、聊天模板或不同修订版。

### 停训、退出与回滚门槛

立即停训：loss 非有限值；梯度持续爆炸；硬件/ECC/通信错误重复；发现无授权或高敏数据；检查点不可恢复；成本超批准上限。

不得上线：目标指标未显著优于基线；通用或安全指标超过容忍回归；成员推断/逐字记忆测试不通过；推理资源使生产 SLO 无法满足；模型卡、数据卡和审批记录不完整。

回滚应删除新路由、恢复旧模型及模板，并隔离失败权重；训练数据删除请求必须传播到派生数据和后续训练计划。已训练模型是否需要重训或退役由法务、数据治理和模型负责人联合裁定。

## 许可与合规边界

许可审查必须覆盖“基础模型、数据、代码与依赖、输出及部署方式”五层，开源不等于可任意商用，本地部署也不自动消除合规义务。

- **基础模型：**确认是否允许商用、微调、合并适配器、量化、修改、内部托管、向关联方或客户提供服务、再分发权重及跨地域使用；记录版本对应的许可文本和核验日期。
- **训练与 RAG 数据：**分别确认复制、解析、向量化、训练、生成衍生物和长期保存的权利；公开可访问不等于可用于训练。个人信息、商业秘密、未公开代码和受版权保护内容须有明确合法基础。
- **代码与依赖：**审查推理引擎、训练框架、算子、驱动、字体、Tokenizer 和容器基础镜像的许可证及相互兼容性，履行署名、NOTICE、源码提供等义务。
- **输出和责任：**模型输出可能含第三方权利内容或个人信息；上线方仍须做内容审核、用途限制和申诉处置，不能将责任全部转移给模型许可方。
- **监管边界：**涉及跨境传输、生成式 AI、网信、密码、数据安全、个人信息、保密或行业监管时，由客户法务、合规、数据保护和信息安全负责人作最终判断。

以下情形必须暂停导入、训练或上线：无法取得许可原文；许可版本与权重版本不匹配；用途超出许可范围；数据来源或授权链不可证明；需要规避地域、行业、用户规模或再分发限制；供应商条款与客户合同冲突；依法需要的评估、备案、授权或审批尚未完成。

实施团队负责提交事实清单、技术数据流、制品来源和控制证据，但不得替客户作法律结论，也不得通过拆分适配器、转换格式、仅内网使用等方式规避许可。所有例外须有书面批准、适用范围、补偿控制、责任人和失效日期。

## 安全治理

### 提示注入与工具安全

- 系统指令、用户输入、检索内容、工具返回值分层标记；网页、邮件、附件中的指令一律视为不可信数据。
- 权限由网关和工具执行器强制校验，不依赖模型“自觉”；工具使用独立短期凭据和最小权限。
- 写入、转账、删除、发信、执行代码等高风险动作采用参数白名单、二次确认或人工审批。
- 限制 URL、文件类型、响应大小、递归调用次数和出站域名；沙箱执行，禁止宿主机特权挂载。
- 用直接注入、间接注入、编码混淆、越权代理、提示提取及多轮诱导测试后方可开放工具。

### 数据外泄防护

- 请求前执行身份、租户、用途及字段级授权；响应前做敏感信息检测、脱敏和策略拦截。
- 禁止将口令、私钥、访问令牌直接写入提示词、训练集、追踪平台或普通日志。
- 对上下文、缓存、会话、向量、日志、备份分别设保存期限和删除 SLA；租户间使用独立命名空间及加密边界。
- 默认关闭供应商遥测和外部回调；确需联网时使用出口代理、域名白名单和流量审计。
- 泄露事件立即停止相关接口、吊销凭据、隔离缓存与索引、通知数据责任人并依法启动通报流程。

### 供应链

- 模型、代码、镜像、驱动、固件及数据均建立来源、版本、许可证、哈希、签名和审批记录。
- 只从批准源导入；下载区、扫描区、签名区、生产仓库分离，双人复核后晋级。
- 生成并留存 SBOM；扫描漏洞、恶意代码、反序列化风险和模型文件中的可执行内容。
- 镜像使用不可变摘要；生产禁止 `latest`、在线临时安装和未审批插件。
- 漏洞修复先兼容性测试与金丝雀；若无法及时修复，记录补偿控制、责任人和到期日。

### 加密与密钥

- 客户端到网关、服务间、跨节点通信使用 TLS；高敏环境启用双向认证。
- 模型权重、数据集、索引、日志、检查点和备份静态加密；优先使用 KMS/HSM 托管密钥。
- 密钥与密文分离；按环境、租户和用途分钥，实施轮换、吊销、恢复及人员离职演练。
- 禁止在镜像、脚本、Git、工单和命令历史中保存明文密钥。

### 审计

至少记录：主体、租户、时间、请求 ID、模型/提示模板/知识库版本、策略判定、工具调用、数据对象、变更审批和结果状态。敏感正文默认不落日志；确需留存须脱敏、加密、限权并明确期限。日志采用集中存储、防篡改、可信时间源和访问留痕；按客户行业规定设置留存期，具体期限由客户法务/合规确认。

### 退役与擦除

1. 冻结新请求并导出依法需保留的审计证据。
2. 撤销路由、服务账户、证书、API Key、KMS 授权和出站规则。
3. 清点权重、适配器、数据集、索引、缓存、检查点、日志、备份及临时盘的全部副本。
4. 依介质和监管要求执行密码擦除、安全覆盖或物理销毁；SSD/加速卡遵循厂商安全擦除能力，不能验证时物理销毁。
5. 对共享备份执行到期淘汰或密钥销毁，并记录不可立即删除的法律保留项。
6. 双人复核资产序列号、擦除方法、时间、工具结果和异常，形成退役证明。
7. 抽样恢复验证“不可恢复”，更新 CMDB、许可证和容量台账。

> 擦除算法、审计期限、跨境和行业监管要求必须由客户法务、合规及数据责任人确认；实施团队不得自行作法律结论。
