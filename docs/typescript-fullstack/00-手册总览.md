# TypeScript 全栈转型与生产实践手册

> 适用对象：希望系统掌握 TypeScript 全栈项目从需求、设计、编码、测试到部署运维全过程的开发者。
> 基线日期：2026-08-27。框架采用“受支持的 Node.js LTS + 锁定的当前稳定大版本”，实际开工前必须复核各项目的引擎约束和迁移指南。

这是一套可按顺序执行的中文手册，不是现成 SaaS 模板。目标是通过逐行手写一个 **AI 增强型多租户协作平台**，掌握从需求、契约和数据库迁移到测试、部署、备份恢复与事故处理的完整闭环。

## 1. 一句话技术路线

1. 用 **React + Vite** 学清浏览器、组件、状态、路由和前后端契约；
2. 用 **NestJS** 构建长期运行的模块化单体主后端；
3. 在掌握前后端分离后学习 **Next.js App Router**，用于 SSR、流式渲染、SEO 和 Web BFF 场景；
4. 三者不是同层替代品：Next.js 不替代复杂业务后端，NestJS 也不负责页面渲染；
5. 起步不采用微服务、Kubernetes 或事件溯源，只有量化瓶颈和 ADR 才能触发升级评估。

## 3. 框架职责速查

| 技术 | 本手册中的职责 | 不承担的职责 |
|---|---|---|
| React | 组件模型、交互状态和 UI 组合 | 构建工具、数据库、服务端授权 |
| Vite | SPA 开发服务器、构建与环境变量边界 | React 运行时、业务后端 |
| NestJS | HTTP API、应用服务、领域规则、事务、后台任务 | 页面 SSR、浏览器组件 |
| Next.js | 第二阶段全栈 Web、SSR/RSC、SEO、Web BFF | 默认替代 NestJS 核心业务后端 |
| PostgreSQL | 关系数据、约束、事务、审计基础 | 用 TypeScript 类型替代数据约束 |

详细决策树见[技术栈基线](01-技术栈基线.md)。若系统只有一个公开内容站点和简单 BFF，可优先 Next.js；若有多客户端、复杂事务、后台任务和稳定 API，保留 NestJS 主后端；需要高交互后台时使用 React + Vite。

## 4. 执行规则

- **掌握驱动，不按天数打卡**：只有通过章节中的可观察标准才进入下一阶段。
- **逐行手写**：AI 可解释、生成反例和评审小 diff，但不可一次生成整层、整模块或全套迁移。
- **契约先行**：HTTP schema、错误码和数据库约束一起评审；不共享 ORM entity。
- **租户隔离默认拒绝**：服务端按租户范围查询，跨租户否定测试是发布门禁。
- **迁移只前进**：生产使用可审查迁移和 Expand–Migrate–Contract；禁止用 schema push 代替迁移。
- **同一制品晋级**：构建一次，经测试后在各环境晋级，不在生产重新构建。
- **恢复能力要演练**：未验证恢复时间与恢复点的备份，不算可用备份。
- **命令均为示意**：手册中的 shell、CI 和 Compose 片段必须按实际仓库、平台和锁定版本调整。

## 7. 维护规则

每次升级 Node.js、TypeScript、pnpm、React、Vite、NestJS、Next.js、ORM 或测试工具时：

1. 先阅读目标大版本的引擎约束、迁移指南和安全公告；
2. 在独立分支升级，保持锁文件可重现；
3. 运行类型、静态检查、迁移、集成、E2E、构建和容器 smoke；
4. 更新[技术栈基线](01-技术栈基线.md)与[资源索引](05-学习资源索引.md)的核验日期；
5. 若改变契约、缓存、认证或数据行为，补 ADR、威胁模型和回滚/前滚方案。
