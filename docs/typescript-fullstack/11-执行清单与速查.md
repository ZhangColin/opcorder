# 11｜执行清单与速查

> 本章是[手册首页](./00-手册总览.md)的执行索引。清单不能替代判断：交付规则见[第 09 章](./09-交付生命周期.md)，部署与事故操作见[第 10 章](./10-部署与运维.md)。

## 1. 使用方法

- 为每项填写 `未开始 / 进行中 / 已证明 / 不适用`，其中“不适用”必须写理由和批准人。
- “已证明”要附 PR、流水线、面板、恢复记录或演练记录，而不是只打勾。
- 首月以掌握标准推进，不要求机械地按自然日完成。
- 生产就绪是持续状态；每次重大架构、数据或平台变化后重评。
- 起步基线始终是模块化单体。微服务、Kubernetes、事件溯源不在本清单的默认答案中。

## 2. 首月启动清单（按四个迭代执行）

“周”代表四个连续迭代，可按团队节奏拉长。目标是形成一个可发布、可观察、可恢复的薄纵向切片，不是赶完课程。

### 第 1 迭代：环境和质量闭环

- [ ] 阅读[手册首页](./00-手册总览.md)，记录个人学习目标、当前能力和需补齐的阶段。
- [ ] 固定 Node.js 主版本、包管理器版本和锁文件策略。
- [ ] 在干净环境完成严格依赖安装、类型检查、lint、测试和构建。
- [ ] 理解 TypeScript 类型擦除；为一个外部输入实现运行时校验并测试失败路径。
- [ ] 理解异步 I/O、事件循环、Promise 错误传播和进程信号。
- [ ] 让 React/Vite 前端与 NestJS API 完成一个最薄请求链路。
- [ ] 建立受保护 `main`、短分支、PR 模板和提交约定。
- [ ] 建立 PR CI：安装、静态检查、单元测试、构建。
- [ ] 写第一个需求卡；若存在不可逆选择，按[ADR 模板](./09-交付生命周期.md#3-adr记录决定不记录会议)记录。

**完成证据**：新成员只凭仓库说明可建立本地环境；故意引入类型、lint、测试错误时 CI 能分别阻断；PR 能追溯到验收条件。

### 第 2 迭代：数据、安全与纵向切片

- [ ] 建立 PostgreSQL 本地/CI 隔离实例和显式迁移流程。
- [ ] 从空库运行全部迁移，并验证上一个 schema 向当前版本升级。
- [ ] 实现一个“页面 → API → 应用用例 → 数据库”的小切片。
- [ ] 在 API 边界做输入校验、统一错误映射和请求 ID。
- [ ] 服务端执行认证、资源授权与租户过滤；测试跨租户拒绝。
- [ ] 为数据库唯一性、并发或状态转换失败编写集成测试。
- [ ] 密钥离开仓库和前端 bundle；应用启动时校验配置。
- [ ] 日志不含 token、密码、敏感请求体或原始个人数据。
- [ ] PR 按[评审顺序](./09-交付生命周期.md#44-评审顺序)完成一次非作者评审。

**完成证据**：成功与至少两个失败路径可重复验证；迁移可在 CI 空库执行；越权请求即使绕过 UI 也被服务端拒绝。

### 第 3 迭代：容器、预发布与可观测性

- [ ] 构建非 root、多阶段、无密钥的容器镜像并扫描。
- [ ] 镜像标注提交 SHA；环境间晋级同一 digest。
- [ ] 实现区分明确的存活/就绪探针和优雅关闭。
- [ ] 建立预发布环境，数据与生产隔离。
- [ ] 建立结构化日志、RED 指标（请求率/错误率/延迟）和最小追踪上下文。
- [ ] 为切片定义一个用户视角 SLI/SLO 草案。
- [ ] 用固定候选制品执行预发布 smoke test。
- [ ] 选择并走通[单机 Compose](./10-部署与运维.md#4-单机-docker-compose-路径)或[托管部署](./10-部署与运维.md#5-托管部署路径)之一。
- [ ] 记录 HTTPS、DNS、证书续期和 secret 轮换责任人。

**完成证据**：能从提交定位运行镜像；一次请求可由 request/trace ID 定位；预发布能安全失败且不调用真实生产外部服务。

### 第 4 迭代：发布与恢复

- [ ] 写一份包含中止阈值、观察面板和责任人的发布计划。
- [ ] 用 expand/contract 设计一次兼容迁移。
- [ ] 定义并由业务负责人批准 RPO/RTO。
- [ ] 备份位于独立故障域，备份失败会告警。
- [ ] 在隔离环境完成一次真实恢复并记录实测 RPO/RTO。
- [ ] 发布候选版本，执行 smoke test、观察和收尾。
- [ ] 回滚到上一镜像 digest，并证明 schema 仍兼容。
- [ ] 桌面推演“错误发布 + 数据库不可达”，明确事故角色。
- [ ] 将发现的问题转成有负责人和期限的改进项。
- [ ] 用本章[生产就绪清单](#5-生产就绪清单)做首次评审。

**完成证据**：团队不是“相信”能回滚和恢复，而是持有演练时间线、校验结果、实测时长与待改进项。

## 3. 能力矩阵

等级定义：

- **L0 了解**：能解释概念和风险。
- **L1 协作**：在指导/评审下完成。
- **L2 独立**：能设计、实现、验证和排障。
- **L3 带领**：能设标准、权衡成本、指导他人并改进系统。

矩阵中的建议目标是首个生产切片完成时的团队覆盖，不要求每个人全部达到。

| 能力域 | L1 可观察行为 | L2 可观察行为 | L3 可观察行为 | 首切片目标 |
|---|---|---|---|---|
| 现代 JS/Node.js | 正确使用模块、Promise、脚本 | 定位事件循环、内存、信号问题 | 制定运行时升级和性能基线 | 至少 2 人 L2 |
| TypeScript | 使用严格类型并处理 `unknown` | 设计泛型/联合类型和运行时边界 | 控制公共类型演化与编译性能 | 全员 L1，1 人 L3 |
| React/Vite | 实现组件、状态和请求 | 处理缓存、错误、可访问性与性能 | 建立前端架构和发布策略 | 至少 2 人 L2 |
| NestJS/API | 编写 module/provider/controller | 设计用例、事务、授权、错误模型 | 治理模块边界与契约兼容 | 至少 2 人 L2 |
| Next.js | 理解路由和渲染模式 | 能选择 SSR/SSG/RSC/Route Handler 边界 | 评估与 NestJS 集成及缓存风险 | 第二阶段至少 1 人 L2 |
| PostgreSQL/ORM | 写迁移和基础查询 | 分析索引、锁、事务和查询计划 | 规划大表变更、容量和恢复 | 至少 2 人 L2 |
| 轻量 DDD | 区分实体、值、用例、边界 | 为核心规则建模并控制依赖方向 | 识别边界变化并主持 ADR | 至少 1 人 L3 |
| 契约与测试 | 编写单元/集成测试 | 设计契约、E2E 和失败场景 | 制定风险门禁并治理不稳定测试 | 全员 L1，2 人 L2 |
| 安全 | 遵守密钥和输入规则 | 实现认证、授权、租户隔离与审计 | 威胁建模、事件处置和例外治理 | 1 人 L3，作者均 L1 |
| CI/CD/容器 | 读懂流水线和镜像 | 独立发布、观察和回滚 | 设计制品供应链与环境治理 | 至少 2 人 L2 |
| 可观测性/SRE | 使用日志和面板排查 | 定义 SLI/SLO、告警和 runbook | 管理错误预算与事故改进 | 至少 2 人 L2 |
| 备份恢复 | 知道 RPO/RTO | 独立执行并校验恢复 | 设计策略、主持跨团队演练 | 至少 2 人 L2 |
| AI Coding 协作 | 审阅生成代码并注明来源 | 用小任务、测试和边界约束 AI | 建立数据安全与评测规范 | 全员 L1，1 人 L3 |

评估方式应使用真实证据：PR、设计说明、故障排查记录、迁移评审和恢复演练。不要用“看过课程”代替能力。

## 4. TypeScript 全栈术语速查

| 术语 | 在本手册中的含义 | 关键提醒 |
|---|---|---|
| Node.js + V8 | 服务端 JavaScript 运行时 | I/O 依赖事件循环；CPU 重任务需隔离 |
| TypeScript compiler | 静态检查与编译配置入口 | 多数类型运行时被擦除 |
| pnpm workspace | Monorepo 包和依赖管理 | 提交唯一锁文件并约束依赖方向 |
| `unknown` / `any` | 未知输入 / 放弃类型检查 | 边界优先 `unknown` 后缩窄 |
| Runtime schema | Zod 等可执行输入契约 | 类型声明本身不会校验 JSON |
| Nest Module / Provider | 后端模块和依赖注册 | scope、生命周期和公开边界需明确 |
| Controller | HTTP 输入输出适配层 | 不直接写 SQL 或承载领域规则 |
| Application Service | 单个业务用例的编排层 | 负责授权、事务和端口调用 |
| Domain Object | 封装核心业务不变量 | 简单 CRUD 不必强造复杂对象图 |
| Prisma Model | PostgreSQL 持久化映射 | 不直接暴露给 API 或前端 |
| Monorepo | 多应用、多包同仓协作 | 同仓不等于同进程或任意共享 |
| Promise / `async`/`await` | 异步结果与流程控制 | Promise 不等于线程；必须处理取消与拒绝 |
| Middleware / Guard / Interceptor / Filter | Nest 请求管线构件 | 执行顺序和职责必须通过测试固定 |
| AsyncLocalStorage | 请求级异步上下文传播 | 不替代显式租户和授权参数 |
| OCI image | 不可变部署制品 | 环境间晋级同一 digest |
| `/live` / `/ready` | 存活与就绪探针 | 避免下游故障触发重启风暴 |
| Migration | 可审查的数据库结构演进 | 已执行迁移不可改写，生产禁止自动同步 |
| OpenTelemetry | 日志、指标和追踪关联标准 | 自动插桩覆盖与异步上下文需实测 |
| Outbox | 数据事务与异步任务的可靠衔接 | 按需引入，不代表微服务或事件溯源 |

## 5. 生产就绪清单

### 5.1 产品与架构

- [ ] 核心用户旅程、失败路径、业务负责人和支持边界明确。
- [ ] 模块化单体边界及依赖方向清晰；无无证据的分布式复杂度。
- [ ] 关键决定有 ADR，包含退出条件。
- [ ] 容量假设、数据增长、外部依赖限额和成本预算已记录。
- [ ] 每个关键能力有降级方式或明确不可降级原因。

### 5.2 契约、数据与迁移

- [ ] API 输入在运行时校验，错误模型一致且不泄露内部信息。
- [ ] 契约变化向后兼容，弃用有期限和使用量观测。
- [ ] 数据库约束保护关键不变量；事务边界明确。
- [ ] CI 可从空库执行迁移，并验证上一发布版本升级。
- [ ] 生产迁移已评估锁、时长、磁盘/WAL 和中止方式。
- [ ] 破坏性变更使用 expand/contract，回滚窗口内保持兼容。
- [ ] 大表回填可暂停、可恢复、有限速并可验证。

### 5.3 安全与隐私

- [ ] 已完成面向资产、入口、信任边界和滥用场景的威胁建模。
- [ ] 认证、授权和租户隔离由服务端执行并有负向测试。
- [ ] 密码采用当前认可的专用哈希；会话可撤销、过期策略合理。
- [ ] secret 不在 Git、镜像、日志、前端 bundle；有轮换和紧急撤销流程。
- [ ] HTTPS、可信代理、CORS、Cookie 和安全响应头配置已验证。
- [ ] 依赖、镜像、许可证、SBOM 和漏洞例外受治理。
- [ ] 日志/追踪已脱敏；数据分类、保留、导出和删除流程明确。
- [ ] 管理与敏感操作进入防篡改、限权访问的审计记录。
- [ ] 云、DNS、代码托管和监控账户启用 MFA 与最小权限。

### 5.4 测试与供应链

- [ ] 核心规则有单元测试，数据库/外部边界有集成或契约测试。
- [ ] 关键用户路径有少量稳定 E2E 和发布后 smoke test。
- [ ] 并发、幂等、超时、重试和权限失败已覆盖。
- [ ] 不稳定测试有隔离、负责人和修复期限。
- [ ] `main` 受保护，必需检查和非作者评审启用。
- [ ] 构建环境和工具版本固定；缓存不影响产物正确性。
- [ ] 制品可追溯到提交、流水线、SBOM 和镜像 digest。
- [ ] 环境间晋级同一制品，没有在服务器上现场构建。

### 5.5 容器、平台与网络

- [ ] 容器多阶段构建、非 root、无密钥、支持优雅关闭。
- [ ] CPU/内存、请求体、超时、连接池和日志大小有边界。
- [ ] 存活与就绪探针语义正确并实际演练失败。
- [ ] 数据库和管理端口不暴露公网；防火墙和网络规则最小化。
- [ ] TLS 自动续期并有到期告警；DNS/证书紧急接管可用。
- [ ] 配置 schema 在启动时验证；预发布与生产数据/secret 隔离。
- [ ] 单机路径可在空主机重建，或托管平台退出/导出路径已记录。
- [ ] 临时磁盘、持久卷、区域、休眠和平台限制均已确认。

### 5.6 可观测性与支持

- [ ] 日志结构化，包含环境、版本和关联 ID，且不含敏感信息。
- [ ] 请求率、错误率、延迟、饱和度及关键业务成功率可视化。
- [ ] 数据库、任务队列和外部依赖有针对性指标。
- [ ] 至少一个关键用户旅程定义 SLI/SLO 和错误预算。
- [ ] 告警可行动，含严重级别、runbook、负责人和升级路径。
- [ ] 外部可用性监控不与应用位于同一故障域。
- [ ] 值守、状态页/用户沟通、供应商升级渠道已经演练。
- [ ] 日志、指标、追踪和审计的保留期与费用有预算。

### 5.7 备份、发布与事故

- [ ] 业务负责人批准 RPO/RTO。
- [ ] 数据库、附件、配置等备份范围完整，副本位于独立故障域。
- [ ] 备份加密、限权、监控并符合保留/删除要求。
- [ ] 隔离恢复演练达到 RPO/RTO，关键不变量校验通过。
- [ ] 发布记录含 digest、迁移、开关、成功/中止指标和责任人。
- [ ] 已演练应用、配置和功能开关回滚；数据回退采用单独决策。
- [ ] 事故分级、指挥、技术、沟通和记录角色明确。
- [ ] 至少完成数据库不可达、错误发布和凭据泄露桌面/预发布演练。
- [ ] 事故复盘无责且改进项有负责人、期限和关闭证据。

## 6. 发布日袖珍清单

### 发布前

- [ ] 确认变更、审批、镜像 digest、迁移和当前生产基线。
- [ ] 确认备份/恢复点、兼容窗口、回滚版本和功能开关。
- [ ] 打开仪表盘，值守与沟通负责人在线。
- [ ] 写明自动或人工中止阈值。

### 发布中

- [ ] 执行兼容迁移，确认锁和时长未越界。
- [ ] 小比例部署并运行 smoke test。
- [ ] 观察错误、延迟、资源、数据库、任务和业务指标。
- [ ] 每次放量后等待约定观察窗口；不同时做无关变更。

### 发布后

- [ ] 验证关键用户旅程和审计记录。
- [ ] 确认无旧版本不兼容、队列积压或异常重试。
- [ ] 记录结果、偏差和后续项；通知相关方。
- [ ] 到达稳定窗口后再安排 contract 迁移和旧开关清理。

## 7. 事故袖珍清单

- [ ] 承认事件、定级、指定指挥官并建立唯一沟通渠道。
- [ ] 记录开始时间、影响范围、当前版本和最近变化。
- [ ] 优先保护数据和凭据，再恢复可用性。
- [ ] 采用已演练的回滚、开关或降级，避免多项盲目修改。
- [ ] 按固定频率更新事实、行动和下次更新时间。
- [ ] 用用户旅程、指标和数据不变量证明恢复。
- [ ] 持续观察，明确事故结束时间与负责人。
- [ ] 安排无责复盘，将改进项纳入正常交付流程。

完成首月清单后，回到[手册首页](./00-手册总览.md)选择下一阶段；任何生产变更继续遵循[第 09 章](./09-交付生命周期.md)的交付证据和[第 10 章](./10-部署与运维.md)的恢复优先原则。
