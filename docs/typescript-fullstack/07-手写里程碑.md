# 07｜逐行手写里程碑

> 导航：[返回手册首页](./00-手册总览.md)｜[项目规格](./06-实战项目规格.md)｜[M0–M1 精确验收](./08-首个纵向切片验收.md)

## 1. 执行规则

里程碑按顺序完成；每一阶段都必须是可运行、可迁移、可测试、可演示的纵向切片。所谓“逐行手写”不是拒绝脚手架，而是要求能解释每一项依赖、配置、迁移、边界和测试。可以查官方文档与让 AI 评审，但不能把模板仓库或 AI 生成的整模块直接纳入主分支。

所有阶段保持 **React + Vite Web + NestJS + PostgreSQL 的模块化单体**。M0–M2 只有 Web 与单一 API 进程；M3 因附件扫描和通知投递才从同一代码库增加 Worker；Redis、对象存储也只能在对应里程碑按 ADR 引入。共享契约只包含 DTO/Schema 与稳定类型，不共享 ORM 实体、Repository 或领域对象。

每一里程碑的统一门禁：

- 静态检查、类型检查、单元、集成和该阶段 E2E 全绿；
- 新表通过前向迁移创建，空库和上一版本库均可升级；
- OpenAPI/共享契约、错误码、权限矩阵和 ADR 同实现一致；
- 日志无 token、密码和正文泄漏；失败路径有显式错误；
- 演示脚本从干净环境执行，保留 CI、迁移和验收证据。

## 2. M0：可重复的工程骨架

**需求**：开发者可一次启动 Web、API 和 PostgreSQL；Web 展示 API 就绪状态；API 提供存活、就绪和版本端点；CI 对干净检出执行质量门禁。

**架构增量**：建立 pnpm workspace、应用与共享包边界、环境变量校验、统一错误响应、结构化日志、数据库迁移框架和测试分层。不得创建业务“万能 common”包。

**严格手写顺序**

1. 写 ADR：为何选模块化单体、React + Vite、NestJS、PostgreSQL。
2. 建 workspace 与最小应用目录，再逐项增加 lint、format、typecheck、test 命令。
3. 手写并验证环境变量 schema，区分开发、测试、生产；提交 `.env.example` 而非秘密。
4. 接数据库与 migration runner，创建仅用于验证迁移生命周期的系统表/扩展。
5. 实现 request id、统一错误模型、`/health/live`、`/health/ready`、`/version`。
6. Web 调用就绪端点并显示 loading/ready/error 三态。
7. 写 API 集成测试、Web 组件测试、一个浏览器 smoke test，最后写 CI。

**测试**：就绪端点在数据库不可用时失败但进程存活；未知路由遵循错误模型；Web 的三种状态；空库迁移和重复迁移；CI 无本地缓存仍通过。

**交付物**：目录边界、ADR、环境样例、迁移、健康/版本契约、测试、CI 定义和启动说明。

**验收**：以 [M0 规格](./08-首个纵向切片验收.md#3-m0可重复工程骨架)为准。

**禁止复制**：成品 SaaS starter、整套 lint/CI 配置、来源不明的 Dockerfile、无法逐项解释的脚手架输出。

## 3. M1：账号、组织与 RBAC 首个纵向切片

**需求**：用户注册、登录、退出；创建组织；查看自己的组织；在当前组织查看成员；`OWNER` 邀请成员；受邀用户接受；非授权角色被拒绝；组织数据互不泄漏。

**架构增量**：新增 Identity、Tenancy & Access 模块；基于 Cookie 的会话、CSRF、密码哈希；用户、会话、组织、成员、邀请表；`TenantContext` 与声明式权限 guard；认证和邀请限流；审计关键操作。

**严格手写顺序**

1. 先写 M1 用例、威胁清单、权限矩阵、状态机和接口契约。
2. 写数据库迁移及约束，再写 Repository 集成测试。
3. 写密码值对象、邀请状态规则、组织成员规则的领域测试。
4. 实现注册/登录/退出与会话轮换；完成后再做对应页面。
5. 实现创建/列出组织和解析当前租户；完成跨租户否定测试。
6. 实现查看成员、创建邀请、接受邀请；每个应用服务先测试再接 Controller/UI。
7. 加 CSRF、速率限制、统一错误、审计和并发验收；最后补浏览器 E2E 与文档。

**测试**：详见 [M1 测试矩阵](./08-首个纵向切片验收.md#47-m1-测试矩阵)，至少覆盖哈希、约束、事务、401/403/404、A/B 租户、邀请过期/重放/并发接受、Cookie 与 CSRF。

**交付物**：迁移、契约、模块实现、Web 页面、种子策略、测试证据、威胁模型、权限矩阵和演示脚本。

**验收**：以 [M1 规格](./08-首个纵向切片验收.md#4-m1账号组织与-rbac)为唯一判定依据。

**禁止复制**：认证 starter、完整 guard/decorator 套件、第三方 RBAC 引擎模板、可直接工作的邀请模块、AI 一次生成整个纵向切片。

## 4. M2：核心协作工作流

**需求**：组织成员创建工作空间和工作项；列表支持游标分页与筛选；负责人编辑标题/描述并按合法状态迁移；成员评论；并发更新不静默覆盖。

**架构增量**：Collaboration 模块、工作项聚合、乐观并发版本、事务内 transition/audit、应用服务公开接口。仍使用同一数据库，不引入消息中间件。

**严格手写顺序**：用例与状态图 → 迁移/约束/索引 → 领域状态测试 → Repository → command/query 应用服务 → REST 契约 → 列表/详情/编辑 UI → E2E → 查询计划复核。

**测试**：非法状态跳转；非成员与跨租户访问；并发更新返回 `409`；分页稳定且无重复；事务失败不留下 transition；键盘操作表单。

**交付物**：状态图、迁移、OpenAPI、索引说明、前后端切片、并发与 E2E 证据。

**验收**：两个组织各 50 个工作项，筛选/分页/授权正确；两客户端冲突可见；状态历史完整。

**禁止复制**：现成 CRUD generator、通用 Repository 基类、绕过聚合直接更新状态、为“未来微服务”提前建 RPC。

## 5. M3：附件、通知与可靠异步

**需求**：授权用户请求上传、完成上传、下载/删除附件；工作项分派和评论产生站内通知与邮件；失败可重试且不重复发送。

**架构增量**：Files、Notifications 模块；S3 兼容对象存储；transactional outbox；同仓库 Worker；病毒扫描状态；通知偏好和死信处置。

**严格手写顺序**：附件威胁模型 → 元数据/通知/outbox 迁移 → 对象键与大小/MIME 校验 → 签名上传完成协议 → outbox 原子写入 → worker claim/幂等 → 站内通知 → 邮件适配器 → UI/E2E → 故障注入。

**测试**：越权对象键、超限和伪造 MIME；未扫描附件不可下载；事务回滚不发通知；worker 崩溃重启不重发；邮件提供商超时进入重试/死信。

**交付物**：上传协议、保留策略、worker、监控指标、失败重放 runbook、测试证据。

**验收**：上传不经过 API 内存转发；任何 URL 不能跨租户下载；连续执行同一任务只产生一次可见通知。

**禁止复制**：公开 bucket、永久下载 URL、进程内“发后即忘”、无来源许可的邮件模板包。

## 6. M4：权限感知搜索

**需求**：用户在当前组织搜索有权查看的工作项、评论和知识文档，可按类型/时间筛选；更新后可在约定延迟内检索。

**架构增量**：Search 模块；先采用 PostgreSQL 全文检索；outbox 驱动增量索引；文档保留 organization 与 ACL metadata。只有容量测试证明不足才引入外部搜索引擎。

**严格手写顺序**：相关性样例 → 权限模型 → 索引迁移 → 文档映射 → 增量索引器 → query service → 高亮/分页 UI → 权限与性能测试 → 重建索引 runbook。

**测试**：跨组织同关键词；工作空间权限变更后结果撤回；特殊字符；稳定分页；百万工作项基线下查询计划与 p95。

**交付物**：搜索契约、相关性样例集、索引器、重建命令、容量报告。

**验收**：权限变化后在定义 SLO 内收敛；组织 B 永远看不到 A 的标题、摘要、计数或高亮。

**禁止复制**：未经评估接入 Elasticsearch、把 SQL 拼接交给客户端、先全局搜索后过滤结果。

## 7. M5：AI 助手与 RAG

**需求**：授权成员添加知识源、查看摄取状态并提问；答案引用来源；无证据拒答；管理员可禁用 AI。

**架构增量**：Knowledge & AI 模块；可替换模型/embedding 端口；异步摄取、切片、向量存储、会话与计量；提示版本化。优先 PostgreSQL + pgvector，容量证据出现后再评估专用向量库。

**严格手写顺序**：威胁/隐私分析 → 20–50 条评测集 → 来源与切片迁移 → 解析/切片 → embedding 适配器 → 带租户 ACL 的召回 → 引用装配 → 回答与拒答 → 流式 UI → token/成本记录 → 红队测试。

**测试**：跨租户泄漏、撤权后检索、提示注入、恶意文档、引用真实性、模型超时/限流、预算耗尽、重复摄取幂等。

**交付物**：模型 ADR、数据处理说明、评测集/基线、提示版本、成本 dashboard、禁用开关和降级 runbook。

**验收**：隔离测试零泄漏；引用可打开且支持答案；达到书面质量阈值；模型故障不影响非 AI 协作功能。

**禁止复制**：未经阅读的 LangChain 示例链、无引用聊天模板、把秘密/完整文档写日志、开放式写操作 Agent。

## 8. M6：用量、套餐与订阅

**需求**：所有者查看席位、存储、搜索和 AI token 用量；套餐额度生效；订阅状态通过支付提供商 webhook 更新；超限行为明确。

**架构增量**：Metering & Billing 模块；不可变幂等 usage event、聚合任务、计划快照、订阅状态机、签名 webhook inbox。支付提供商是适配器，不自行处理卡号。

**严格手写顺序**：计量语义/边界 → 迁移与幂等约束 → 事件记录 → 聚合对账 → quota decision service → 用量 UI → webhook 签名/重放防护 → 订阅 UI → 月结与修正流程。

**测试**：重复/乱序 webhook；跨月时区；并发扣额；退款/取消；聚合可由原始事件重算；支付方不可用。

**交付物**：计量字典、状态图、对账报告、测试支付演示、人工修正审计流程。

**验收**：重复消息不重复计费；聚合和明细可对账；额度拒绝不会留下半成品操作。

**禁止复制**：浮点金额、仅靠前端限额、把 webhook 当同步控制流、伪造支付成功。

## 9. M7：后台、审计与生产能力

**需求**：平台运营查看租户健康/用量，处理受审计的支持操作；租户管理员查看组织审计；完成发布、监控、备份恢复和事故演练。

**架构增量**：Audit & Operations 模块；平台身份域隔离；append-only 审计；短期 support grant；OpenTelemetry；生产镜像、CI/CD、迁移作业、告警与恢复流程。仍默认单机 Compose 或托管容器，不以 Kubernetes 为毕业条件。

**严格手写顺序**：运营用例/越权威胁 → 审计 schema/保留 → 平台授权 → 只读后台 → 支持授权审批 → 指标/追踪/告警 → 镜像与 SBOM → 发布/回滚 → 备份恢复 → 故障演练。

**测试**：平台与租户角色混淆；审计篡改；支持授权过期；迁移失败回滚；数据库/对象存储/模型/邮件故障；从备份恢复并核对抽样数据。

**交付物**：后台、审计导出、dashboard、告警、SBOM、部署与回滚记录、恢复报告、事故复盘。

**验收**：非作者按 runbook 完成部署和恢复，满足 RPO/RTO；所有后台写操作有理由、操作者和关联工单；无租户正文出现在运营列表或指标。

**禁止复制**：无授权的“超级管理员”、直接生产库手改、只截图不演练的备份、为展示而引入 Kubernetes/微服务。

## 10. 何时可以进入下一阶段

只有当前里程碑的需求、自动化测试、迁移、文档、可观测性和否定路径全部验收，才能进入下一阶段。未解决项必须进入显式风险清单并有负责人和期限；不得以“以后补测试/安全/隔离”作为通过理由。M0 与 M1 的粒度和证据格式以[下一章](./08-首个纵向切片验收.md)为准，后续阶段应复用其任务拆分模板。
