# 04｜按先修关系推进的学习路径

> 导航：[手册总览](00-手册总览.md) · [资源索引](05-学习资源索引.md)

本路径面向希望系统掌握 TypeScript 全栈交付的开发者。它不是“30 天打卡表”：只有通过当前阶段的**可观察掌握标准**，才进入后继阶段。所有练习都应新建在独立学习仓库中逐行键入；不要复制生成成品，也不要修改任何既有产品。

## 1. 路径图与执行规则

```text
S0 工具与 Web 基础
 └─S1 JavaScript 与 Node.js
    └─S2 TypeScript
       └─S3 pnpm / Monorepo / 工程质量
          ├─S4 React + Vite ─────────┐
          └─S5 NestJS ──S6 数据库 ──┼─S7 契约、测试与安全
                                    ├─S8 Next.js 专项
                                    └─S9 AI 应用工程
                                       └─S10 生产交付与可观测性
```

- **顺序原则**：S4 与 S5 可交换或并行；S6 必须在 S5 后；S7 必须等前后端和数据路径都能独立运行。
- **手敲原则**：脚手架只负责初始化；配置、领域类型、路由、测试、迁移和 Dockerfile 要逐行写，并能解释每一行。AI 可以评审、提问和生成测试清单，不能代替首次实现。
- **证据原则**：每阶段保留 README、命令记录、失败案例、测试结果和一页复盘。以行为证据而非看完课程作为完成。
- **架构护栏**：起步只做模块化单体、单一 PostgreSQL 和少量进程。不要引入微服务、Kubernetes、事件溯源；先证明单体的模块边界、测试、部署或容量已成为可测量瓶颈。
- **版本原则**：命令中的版本应按仓库锁文件与引擎约束确定，不照抄课程里的旧大版本。版本资料见[资源索引的核验规则](05-学习资源索引.md#核验口径与使用方法)。

## S0｜工具、协议与关系数据基础

**先修**：能使用一种主流代码编辑器和命令行；无需已有后端框架经验。

**知识**：Git 分支/提交/回退，Shell 与进程退出码，HTTP 方法/状态码/头/Cookie/CORS，JSON，SQL 的连接、约束、事务和索引，浏览器开发者工具。

**逐行手敲练习**
1. 新建空仓库，手写 `.gitignore`、编辑器配置和学习日志；制造一次冲突并用 `rebase` 解决，再用 `reflog` 找回误删提交。
2. 只用 `curl` 调一个公开 HTTP API：保存请求/响应头，解释缓存、认证失败与限流状态；禁止先用 Postman 隐藏协议细节。
3. 在本地 PostgreSQL 手写建表、外键、唯一约束、事务回滚、组合索引及 `EXPLAIN`；构造一条失败约束并记录错误。

**掌握标准**
- 能从网络面板重放一个请求，并区分 400、401、403、404、409、422、500。
- 能解释“数据库约束为何不能只靠应用校验”，并用执行计划说明索引是否命中。
- 能从 detached HEAD、冲突或误提交中恢复，不删除仓库重来。

**常见误区**：把 HTTP Controller 当远程方法调用；把 GUI 操作等同于理解 Git/SQL；看到查询慢就加索引；将 401 与 403 混用。

## S1｜现代 JavaScript 与 Node.js 运行时

**先修**：通过 S0；能从命令行启动、停止进程并读取环境变量。

**知识**：值与引用、原型、闭包、模块、解构与迭代器；Promise、`async/await`、事件循环、微任务；ESM/CJS 边界；Node 的文件、流、Buffer、进程、错误和取消。

**逐行手敲练习**
1. 不用 TypeScript 写一个 ESM 命令行程序：读取大文本流、逐行统计、支持参数和非零退出码；分别制造文件不存在、权限和中断错误。
2. 手写 Promise 并发限制器；记录同步代码、微任务、计时器的执行顺序，再用实测修正预测。
3. 用 `AbortController` 为一个 HTTP 请求加超时；确保资源清理，并区分业务失败、超时和程序缺陷。

**掌握标准**
- 不运行代码也能正确预测典型闭包与事件循环题，并用实验验证。
- 能解释 ESM、CJS、`package.json` 的 `type` 与导入扩展名为何会互相影响。
- 流式处理大文件时内存不随文件大小线性增长；异常能传至进程边界。

**常见误区**：把 Promise 当线程；到处 `await` 导致串行；忘记返回 Promise；把 Node 当浏览器或把 `undefined` 当 `null`；捕获错误后静默吞掉。

## S2｜TypeScript：从类型标注到边界建模

**先修**：通过 S1；能先用 JavaScript 完成相同练习。

**知识**：类型推断、联合/交叉、收窄、泛型、结构化类型、条件/映射类型、`unknown`/`never`；严格模式；类型擦除；声明文件；编译器与运行时边界。

**逐行手敲练习**
1. 将 S1 CLI 迁移到严格 TypeScript；禁止 `any`、非空断言和无解释类型断言。
2. 为“草稿—已提交—已取消”建判别联合，写穷尽 `switch`；添加新状态并让编译器指出所有遗漏分支。
3. 从一段未知 JSON 开始：先保持 `unknown`，手写最小类型守卫和失败信息；证明 `as SomeType` 不会做运行时校验。
4. 编写一个泛型结果类型和错误联合，只表达必要失败状态，不堆砌无行为的类层级。

**掌握标准**
- 项目开启严格检查，能说明每个编译器选项的目的；无未经审查的 `any`。
- 能选择联合、接口、类型别名、泛型和类，而非全部用 class。
- 外部输入必须经运行时校验后才进入可信类型；能演示类型擦除。

**常见误区**：把类型标注当运行时校验；以 `as` 消除所有错误；滥用 enum、装饰器和复杂类型体操；误以为 `private` 或接口在运行时存在；用可选字段代替状态机。

## S3｜pnpm、Monorepo 与工程质量基线

**先修**：通过 S2；能解释编译、打包、运行三个阶段。

**知识**：`package.json`、semver、锁文件、workspace、依赖/开发依赖/peer dependency；tsconfig 分层；lint/format/typecheck/build/test；供应链与可复现安装。

**逐行手敲练习**
1. 用 pnpm workspace 建 `apps/web`、`apps/api`、`packages/contracts` 三个空包，只共享类型与校验契约，不共享框架内部实现。
2. 手写根脚本，使 `lint → typecheck → test → build` 任一步失败都返回非零状态；从干净目录用冻结锁文件恢复。
3. 制造未声明依赖、循环依赖和不兼容 peer dependency，观察并修复；用 overrides 记录一次临时安全修复及移除条件。

**掌握标准**
- 能解释为何只提交一个锁文件、何时发布包、何时只做 workspace 内部包。
- CI 与本地执行同一组命令；删除缓存后仍可复现。
- 能画出 `apps → contracts` 的单向依赖图，业务模块之间没有“万能 shared”。

**常见误区**：把 Monorepo 当单个巨型包；全局安装工具；随意删除锁文件；错误使用 `^` 升级框架大版本；过早引入复杂构建编排器。

## S4｜浏览器、React 与 Vite

**先修**：通过 S3；熟悉 DOM、事件、表单、HTTP 与基础 CSS。若缺失，先补 S0 的浏览器部分。

**知识**：组件纯度、JSX、props/state、不可变更新、渲染/提交、Effect 生命周期、受控表单、路由、服务端状态、可访问性；Vite 的开发服务器与生产构建边界。

**逐行手敲练习**
1. 先用原生 DOM 写筛选表格和可访问表单，再用 React 重写；逐项比较状态、事件与 DOM 更新。
2. 用 Vite 建最小 React 应用，手写列表/详情/编辑路由；刷新深层 URL 仍能正确由服务器回退。
3. 接入一个真实测试 API：实现 loading/error/empty/success 四态、取消过期请求和表单服务端错误；先用原生 Effect，再用查询库重构并说明收益。
4. 为键盘操作、焦点、label、错误提示写测试；用 React DevTools 找出一次多余渲染。

**掌握标准**
- 不用 Effect 派生可计算状态；依赖数组正确，Strict Mode 下无重复副作用。
- 刷新、后退、慢网、失败和重复提交均有明确行为。
- 组件测试关注用户行为而非内部 state；核心页面可只用键盘完成。

**常见误区**：把 React 组件当长期存活的可变对象；所有状态全局化；在 Effect 内同步 props；把 Vite 开发代理当生产网关；过度 `useMemo`；把服务端数据缓存与本地 UI 状态混为一谈。

## S5｜NestJS 模块化单体与轻量 DDD

**先修**：通过 S3、理解 HTTP；S4 可并行。

**知识**：Module、Controller、Provider 与 DI；请求管线；DTO 校验、认证/授权、异常映射；应用服务、领域规则、仓储端口；配置、日志、优雅关闭；模块化单体边界。

**逐行手敲练习**
1. 初始化单个 Nest 应用，手写健康检查、配置校验、结构化错误响应和 request ID。
2. 建两个业务模块：Controller 只做协议适配，应用服务编排用例，领域对象维护不变量，基础设施实现仓储端口；禁止跨模块直接访问内部仓储。
3. 实现一个带乐观并发条件的更新用例；分别测试成功、不存在、冲突、无权限和非法转换。
4. 写全局输入校验、异常过滤与授权守卫；证明“已认证”不等于“有资源权限”。

**掌握标准**
- 能从 HTTP 请求追踪到 Controller、应用服务、领域规则、仓储和响应，并说清事务边界。
- 核心规则不依赖 Nest 装饰器也能单测；简单 CRUD 不强造聚合/值对象。
- 模块之间通过公开应用接口或契约协作，未拆网络进程仍保持清晰边界。

**常见误区**：让 Service 无所不包；每张表都是聚合；Repository 返回任意查询器；以装饰器数量代表架构；滥用 request scope；一开始拆微服务/CQRS/事件溯源。

## S6｜PostgreSQL、迁移与 ORM

**先修**：通过 S5 与 S0 SQL 验收。

**知识**：关系建模、约束、隔离级别、锁、并发、索引；schema migration 与数据迁移；连接池；N+1；ORM 生成类型与真实数据库语义的边界；多租户行级过滤。

**逐行手敲练习**
1. 先手写 SQL 模型与约束，再映射到 ORM；生成首个迁移，检查 SQL 后执行，不用 schema push 代替可审计迁移。
2. 写一条跨两表的事务用例，注入中途失败并证明原子回滚；并发执行更新，观察丢失更新后加版本条件。
3. 构造 N+1 和缺索引查询，记录 `EXPLAIN (ANALYZE, BUFFERS)` 前后差异。
4. 为所有租户数据查询显式传入 tenant ID；写“甲租户不可读乙租户”的集成测试。

**掌握标准**
- 空库可通过迁移重建；已有数据可前滚；破坏性变化采用 expand/migrate/contract。
- 能识别事务过长、连接泄漏、N+1 与全表扫描。
- 数据隔离由数据库约束、仓储过滤和测试共同保证，而非仅靠前端隐藏。

**常见误区**：把 ORM 当数据库；编辑已发布迁移；生产自动 `sync`；以单元测试替代真实数据库集成测试；把每次请求开成超长事务。

## S7｜共享契约、测试金字塔与安全

**先修**：通过 S4、S5、S6；已有一条浏览器到数据库的最小路径。

**知识**：运行时 schema 与类型推导；OpenAPI/契约演进；错误模型；单元、集成、契约、E2E 的职责；认证、对象级授权、CSRF/XSS/CORS、速率限制、依赖审计、秘密管理。

**逐行手敲练习**
1. 在共享契约包定义请求/响应 schema，由前后端各自解析；故意破坏字段，保证契约测试先失败。
2. 为一条纵向切片写：纯领域单测、真实 PostgreSQL 集成测试、API 契约测试、浏览器 E2E；记录每层捕获了什么。
3. 建威胁表：资产、入口、攻击者、滥用场景、控制措施、残余风险；手测越权、批量赋值、恶意 HTML、超大输入和重复请求。
4. 轮换一个本地测试密钥，确保仓库、日志、错误响应均不出现秘密。

**掌握标准**
- 外部输入在进程边界做运行时验证；共享类型不能替代验证。
- CI 可稳定复现四类测试；失败信息能定位层次；没有依赖生产数据的测试。
- 对每个写操作能回答“谁、对哪个租户的哪个资源、在何条件下可以做”。

**常见误区**：只测覆盖率；E2E 包办一切；快照大面积替代断言；JWT 有效即授权成功；将 CORS 当认证；在前后端复制相似但漂移的 DTO。

## S8｜Next.js：第二阶段全栈 Web 框架

**先修**：通过 S4；完成 S5/S7 可获得完整对比。不得跳过 React/Vite 直接背 Next.js 约定。

**知识**：App Router、Server/Client Components、布局、导航、缓存与重新验证、Route Handler、Server Action、SSR/SSG；部署运行时与 NestJS 的边界。

**逐行手敲练习**
1. 把 S4 的一个公开只读页面重做为 App Router 页面，分别观察构建期、服务端和浏览器日志，标注代码实际运行位置。
2. 对同一数据分别做动态渲染、静态生成与按需重新验证；记录新鲜度、成本和失效行为。
3. 做一个 BFF 式 Route Handler 调用既有 Nest API，传递认证与 request ID；不得复制核心业务规则。
4. 写 ADR：比较“Vite SPA + Nest”“Next + Nest”“仅 Next”在 SEO、团队边界、长事务/后台任务和部署复杂度上的取舍。

**掌握标准**
- 能准确判断模块运行在 server、client、edge 或 build，并避免秘密进入客户端包。
- 能解释缓存键、失效条件与用户隔离；不会缓存租户私有响应给其他用户。
- 知道 Next.js 与 NestJS 不是同层替代：前者偏 React 全栈 Web/渲染，后者偏结构化后端。

**常见误区**：所有组件都加 `use client`；套用旧 Pages Router 教程；不理解缓存就上线；在 Next 与 Nest 重复领域逻辑；为“统一”而强迫所有页面 SSR。

## S9｜AI 应用工程

**先修**：通过 S6/S7；能做权限隔离、异步取消、结构化日志和成本统计。

**知识**：模型 API、流式响应、结构化输出、工具调用、提示注入；embedding、分块、检索、引用；评测集、延迟/成本/质量三角；数据最小化与人工确认。

**逐行手敲练习**
1. 用官方 SDK 写最小流式调用，支持超时、取消、重试上限和用量记录；密钥只从服务端环境读取。
2. 对固定小语料手写“切分→向量化→检索→带引用回答”管线；保留原文定位并验证租户过滤先于检索。
3. 建 20 条固定评测样例，含无答案、越权诱导、提示注入和超长输入；每次改提示或模型后重跑。
4. 工具调用只允许白名单、严格参数 schema；写操作先预览并要求用户确认。

**掌握标准**
- 输出失败、拒答、取消与降级都可观测；重试不会造成无限费用或重复写入。
- 能用固定评测比较变更，而非凭演示观感；答案能追溯引用。
- 模型不能绕过既有认证授权；敏感数据去向、保留期和删除路径清楚。

**常见误区**：把提示词当业务授权；先上框架再懂基础 API；盲目重试；只测“看起来不错”；把向量库当事实来源；把供应商响应全文写日志。

## S10｜生产交付、可观测性与演练

**先修**：通过 S7；若含 AI 能力则还需 S9。

**知识**：多阶段镜像、非 root、Compose；CI 门禁、迁移顺序、HTTPS、配置与秘密；日志/指标/追踪；SLO 与告警；备份恢复、滚动发布与回滚；容量和事故响应。

**逐行手敲练习**
1. 手写前后端多阶段 Dockerfile 与单机 Compose：应用、PostgreSQL、反向代理；固定镜像版本、健康检查、持久卷和资源限制。
2. 手写 CI：冻结依赖、lint/typecheck/test/build、镜像扫描；用临时数据库执行迁移和集成测试。
3. 接入 request ID、结构化日志、RED 指标和一条跨 HTTP/数据库的 trace；告警必须指向 runbook。
4. 完成三次演练：从备份恢复到新库并校验；发布失败回滚；数据库不可用时限流/降级并复盘 RTO/RPO。

**掌握标准**
- 一台干净机器可按文档部署；没有手工修改容器内文件的步骤。
- 能从用户错误跳转到日志、指标、trace；高基数租户 ID 不误作指标标签。
- 恢复演练实测满足声明的 RPO/RTO；数据库变更与应用回滚兼容。

**常见误区**：能构建镜像即生产就绪；只备份不恢复；使用 `latest`；在日志中记录令牌/提示全文；无流量基线就设告警；起步上 Kubernetes 或为部署拆微服务。

## 2. 跨阶段能力门

进入真实纵向切片前，进行一次不看教程的综合验收：

1. 从空目录建立 workspace、Vite Web、Nest API、共享运行时契约和 PostgreSQL 迁移。
2. 完成一个含认证、租户过滤、乐观并发和四态 UI 的写操作。
3. 同时提交领域单测、真实数据库集成测试、契约测试和一条 Playwright E2E。
4. 用 Compose 启动，采集同一请求的关联日志与 trace，备份并恢复数据。
5. 提交 ADR 解释为何当前仍采用模块化单体，以及触发拆分的可测量条件。

任一项只能靠复制模板、无法解释失败路径，均应回到对应阶段。完成后从[资源索引](05-学习资源索引.md)挑选专项材料补缺，而不是继续横向收集课程。
