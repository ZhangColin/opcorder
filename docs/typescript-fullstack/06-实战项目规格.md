# 06｜贯穿项目规格：AI 增强型多租户协作平台

> 导航：[返回手册首页](./00-手册总览.md)｜[下一章：手写里程碑](./07-手写里程碑.md)｜[M0–M1 验收规格](./08-首个纵向切片验收.md)

## 1. 项目目标与边界

本项目是用于学习和交付演练的独立 SaaS：团队在工作空间内创建“工作项”，按受控状态流协作，沉淀附件和知识，并在后续阶段使用带来源引用的 AI 助手检索组织知识。

它要覆盖账号、组织、RBAC、事务工作流、对象存储、通知、搜索、RAG、计量订阅和审计等常见生产问题，但刻意压低业务花样。它不是项目管理套件、即时通信工具、网盘、财务系统或通用 AI Agent 平台。

### 必须提供

- 用户注册、登录、退出和会话管理；
- 组织（即租户）创建、成员邀请、角色授权和组织切换；
- 工作空间与工作项的创建、分派、状态流转、评论；
- 附件上传、站内/邮件通知、组织内搜索；
- 基于组织知识的问答，答案必须给出可访问的来源；
- 用量统计、套餐额度与订阅状态；
- 平台后台、租户审计、基本可观测性和运维能力。

### 明确不做

- 自定义工作流设计器、甘特图、实时多人编辑、私聊和音视频；
- 跨组织协作、组织层级/集团树、复杂 ABAC；
- 自建支付清算、模型训练、通用插件市场；
- 起步即微服务、Kubernetes、事件溯源或 CQRS 双存储。

## 2. 用户与权限角色

| 角色 | 作用域 | 主要能力 |
|---|---|---|
| 访客 | 未登录 | 注册、登录、接受有效邀请 |
| 普通用户 | 全局身份 | 管理本人资料、查看自己的组织列表 |
| `OWNER` | 单一组织 | 组织设置、成员和角色、套餐；每组织至少一名 |
| `ADMIN` | 单一组织 | 成员、工作空间和内容管理；不能转移所有权 |
| `MEMBER` | 单一组织 | 按工作空间成员关系协作 |
| 平台运营 `PLATFORM_ADMIN` | 平台 | 查看租户状态、审计和用量；不默认读取租户正文 |
| 平台支持 `PLATFORM_SUPPORT` | 平台 | 经授权、限时、全审计地协助排障 |

`OWNER/ADMIN/MEMBER` 是组织成员角色，不写入用户全局身份。平台角色与租户角色完全分离。工作空间可再限制成员范围，但 M1 仅实现组织级角色。

## 3. 关键用户旅程

1. 用户注册并登录，创建组织后自动成为 `OWNER`。
2. 所有者邀请成员；成员接受邀请后进入组织并获得指定角色。
3. 成员创建工作空间和工作项，将工作项分派给组织成员。
4. 工作项按 `TODO → IN_PROGRESS → DONE` 流转；重开为 `DONE → IN_PROGRESS`，每次变更可追溯。
5. 成员评论、上传附件；相关成员收到通知。
6. 成员搜索自己有权访问的工作项、评论和知识文档。
7. 成员向 AI 助手提问；系统仅从当前组织且当前用户可见的知识中检索，回答附来源，证据不足时明确拒答。
8. 所有者查看用量和额度；平台运营查看不含租户正文的运行状态与审计。

## 4. 限界上下文与模块化单体

最终首发形态可包含一个 NestJS API 进程、一个同代码库异步 Worker、一个 React + Vite Web 应用、一个 PostgreSQL 数据库，以及按需启用的 Redis 与 S3 兼容对象存储。引入时间线是硬约束：**M0–M2 只有 Web + API + PostgreSQL；M3 因附件扫描/通知投递首次引入 Worker 与对象存储；Redis 仅在经过 ADR 证明队列、缓存或限流需要时引入，M0–M1 不用于会话。**代码始终按上下文分模块，模块之间只能调用公开应用服务或发布进程内通知；M3 后跨进程可靠任务使用 outbox，禁止跨模块直接访问 Repository。

| 上下文/模块 | 责任 | 拥有的数据 |
|---|---|---|
| Identity | 凭据、会话、邮箱验证、密码重置 | `users`、`credentials`、`sessions` |
| Tenancy & Access | 组织、成员、邀请、RBAC、当前租户 | `organizations`、`memberships`、`invitations` |
| Collaboration | 工作空间、工作项、状态流、评论 | `workspaces`、`workspace_members`、`work_items`、`comments`、`work_item_transitions` |
| Files | 上传授权、对象元数据、病毒扫描状态 | `attachments` |
| Notifications | 通知偏好、站内通知、邮件投递 | `notifications`、`notification_deliveries` |
| Search | 权限过滤后的检索索引 | `search_documents` 或外部索引 |
| Knowledge & AI | 知识源、切片、向量、对话、引用 | `knowledge_sources`、`knowledge_chunks`、`ai_conversations`、`ai_messages`、`ai_citations` |
| Metering & Billing | 计量事件、聚合用量、套餐、订阅 | `usage_events`、`usage_aggregates`、`plans`、`subscriptions` |
| Audit & Operations | 不可变审计、后台操作、支持授权 | `audit_logs`、`support_grants` |

这些是代码和所有权边界，不是服务拆分清单。只有当独立扩缩容、故障隔离或团队自治的收益有测量证据，且具备分布式追踪、幂等、消息可靠性和独立部署能力后，才讨论拆服务。

### 模块实现规则

| 构件 | 本项目中的职责 | 边界 |
|---|---|---|
| Nest Module | 组织进程内业务模块及依赖 | 不是服务拆分单位 |
| Controller | HTTP 协议适配 | 不承载事务脚本或数据库查询 |
| Application Service | 用例编排、授权和事务边界 | 不泄漏 HTTP/ORM 细节 |
| Domain Object | 维护核心不变量 | 不依赖 NestJS 装饰器 |
| Prisma Model | 数据持久化映射 | 不直接作为 HTTP DTO 或领域对象 |
| Runtime Schema | 校验外部输入并推导类型 | TypeScript 类型不能替代运行时校验 |
| Guard + TenantContext + Policy | 认证、租户建立和资源授权 | 前端隐藏按钮不能替代服务端裁决 |
| 进程内通知 / Outbox | 模块协作或可靠异步投递 | 不等于事件溯源，也不要求起步使用消息代理 |

## 5. 核心数据规则

- 主键使用不可预测的 UUID；数据库时间统一为 UTC，接口使用 ISO 8601。
- 所有租户业务表必须有不可空 `organization_id`；全局身份表例外。
- 邮箱比较使用规范化值并建立唯一约束；原始展示值可另存。
- `memberships` 对 `(organization_id, user_id)` 唯一；状态为 `ACTIVE/SUSPENDED`。
- `invitations` 保存 token 摘要而非明文，并有过期时间、接受时间；同组织同邮箱至多一个有效邀请。
- 工作项必须属于一个工作空间，工作空间与工作项的 `organization_id` 必须一致。
- 被指派人必须是同组织有效成员；状态变更与 transition 记录在同一事务提交。
- 附件数据库只存元数据和对象键，不存文件字节；下载使用短期签名 URL。
- 计量事件必须带幂等键；金额使用最小货币单位整数，不使用浮点数。
- 审计日志记录 actor、organization、action、target、request/correlation id、时间和必要差异；不记录密码、token、附件正文或 AI 原始密钥。
- 业务记录默认不硬删除；涉及个人数据删除时执行可审计的匿名化/保留策略。

## 6. 租户隔离模型

租户隔离不是只加一个查询条件，而是以下共同约束：

1. **上下文建立**：认证中间件只确认用户；请求中的组织标识必须再通过活动 membership 解析为 `TenantContext`。不得相信客户端提交的角色。
2. **显式传递**：应用服务的租户操作必须接收 `organizationId` 和 actor；禁止从全局变量隐式取租户。
3. **数据访问**：所有租户 Repository 方法都要求租户参数；按 `organization_id` 建联合索引和唯一约束，外键尽可能包含组织列。
4. **纵深防御**：生产 PostgreSQL 启用并测试 Row Level Security（RLS）；应用事务开始时设置当前组织，连接归还池前清理。RLS 不能替代应用层授权。
5. **外部资源**：对象键、缓存键、搜索文档、向量 metadata、队列任务都必须含组织标识；消费任务时重新建立租户上下文。
6. **日志与指标**：日志可记录组织 ID，不记录租户敏感正文；指标不得使用组织 ID 作为无界 label。
7. **平台访问**：平台管理员不得伪装为租户成员。支持访问要求工单原因、时间范围和最小权限，并产生审计。

隔离测试必须构造组织 A、B 和同时属于二者的用户，覆盖读、列表、更新、删除、附件、搜索、缓存、异步任务和 AI 检索；所有“改 URL 中的 ID”尝试均返回不泄漏对象是否存在的 `404`（身份未认证返回 `401`，组织成员权限不足返回 `403`）。

## 7. 授权矩阵（首版）

| 操作 | OWNER | ADMIN | MEMBER |
|---|---:|---:|---:|
| 读取组织及成员 | ✓ | ✓ | ✓ |
| 修改组织设置 | ✓ | ✓ | — |
| 邀请/停用成员 | ✓ | ✓ | — |
| 修改角色 | ✓ | 仅 MEMBER | — |
| 转移所有权/删除组织 | ✓ | — | — |
| 创建工作空间/工作项 | ✓ | ✓ | ✓ |
| 管理全部工作项 | ✓ | ✓ | — |
| 编辑本人创建/负责的工作项 | ✓ | ✓ | ✓ |
| 查看用量 | ✓ | ✓ | — |
| 管理订阅 | ✓ | — | — |
| 查看租户审计 | ✓ | ✓ | — |

服务端是授权唯一裁决者；前端隐藏按钮只是体验优化。所有对象级操作还要验证对象属于当前组织及当前用户可见的工作空间。

## 8. 非功能要求与发布指标

下表是 **M7 生产演练的最终目标**，不是 M0–M1 的容量、SLO 或 AI 验收门槛。M0–M1 只执行[首个纵向切片规格](./08-首个纵向切片验收.md)中的功能、安全与质量门禁。

| 类别 | 最低要求 |
|---|---|
| 可用性 | 月度 API 可用性目标 99.9%；健康检查区分存活与就绪 |
| 性能 | 常规 API 在正常负载下 p95 < 400 ms；搜索 p95 < 1 s；AI 首 token p95 < 5 s（外部模型依赖单列） |
| 容量 | 初始验证基线：1,000 组织、10 万用户、100 万工作项；通过分页和索引而非一次加载 |
| 一致性 | 身份、成员、工作流采用数据库事务；邮件、索引、AI 摄取用 transactional outbox + 幂等消费者实现最终一致 |
| 安全 | TLS、Argon2id 密码哈希、HttpOnly/Secure/SameSite Cookie、CSRF 防护、速率限制、输入验证、依赖与镜像扫描 |
| 隐私 | 数据最小化、可导出/删除、日志脱敏；AI 提供商不得默认用于训练，传输内容与保留期可配置 |
| 可观测性 | 结构化日志、request id、RED 指标、数据库/队列/外部 AI tracing；错误可定位到版本和请求 |
| 恢复 | PostgreSQL 每日全量 + PITR；对象存储版本化；目标 RPO ≤ 15 分钟、RTO ≤ 4 小时，并季度恢复演练 |
| 可访问性 | 核心流程键盘可操作，表单有标签与错误关联，目标 WCAG 2.1 AA |
| 兼容性 | 支持当前及前一主版本的 Chrome/Edge/Firefox/Safari；API 在演练周期内保持向后兼容 |

## 9. AI/RAG 专项护栏

- 摄取只接受用户有权添加的来源，切片和 embedding 均带 `organization_id`、source id 与 ACL metadata。
- 检索先做租户和权限过滤，再重排；不得先跨租户召回后在应用层丢弃。
- 回答必须返回来源标题、稳定引用 ID 和可授权访问的链接；无足够证据时说明“不知道”。
- 外部内容视为不可信输入，系统提示明确忽略文档中的指令；工具调用采用白名单且默认只读。
- 记录模型、提示模板版本、token 数、耗时和结果状态；提示与回答正文按隐私策略保存，不能进入普通日志。
- 自动化评测至少覆盖答案依据性、引用正确性、跨租户泄漏、提示注入、拒答和成本上限。

## 10. 完成定义

平台达到“生产演练完成”须满足：

- [ ] [手写里程碑](./07-手写里程碑.md) 全部通过，M0–M1 另按[精确验收规格](./08-首个纵向切片验收.md)执行；
- [ ] 每个上下文有明确所有者、公开接口和禁止依赖，仍以模块化单体部署；
- [ ] 租户隔离、RBAC、迁移、备份恢复、安全扫描和故障演练有自动化或可复现证据；
- [ ] 搜索与 AI 的权限测试证明组织 A 的任何内容不会出现在组织 B；
- [ ] 指标、告警、runbook、发布和回滚流程由非作者执行成功；
- [ ] 无微服务、Kubernetes、事件溯源等与当前规模无关的前置复杂度。
