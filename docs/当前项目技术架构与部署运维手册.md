> 文档性质：面向开发、交接、部署与运维的项目事实说明  
> 基线日期：2026-08-28  
> 适用仓库：当前 pnpm Monorepo  
> 核心产品：接单吧 OPC 撮合交易平台

## 1. 文档目的

本文档回答以下问题：

1. 当前项目实际使用了哪些技术；
2. 源码目录如何组织，各包之间如何依赖；
3. 前端、API、数据库、对象存储和外部服务如何协作；
4. 在 Replit 中如何开发、构建和发布；
5. 下载源码后，如何在其他 Linux 环境部署；
6. 数据库迁移、定时任务、备份恢复和日常运维需要注意什么。

本文只描述当前仓库，不使用通用培训手册中的 NestJS、Prisma、Next.js 或 Docker 示例替代项目事实。

## 2. 系统一句话架构

接单吧是一个 TypeScript pnpm Monorepo：

- 浏览器端使用 React 19 + Vite 7 构建 SPA；
- 服务端使用 Node.js + Express 5 提供 REST API；
- PostgreSQL 保存业务数据，Drizzle ORM 定义数据库结构；
- OpenAPI 是接口契约来源，通过 Orval 生成前端 React Query 客户端和服务端 Zod 校验器；
- 文件通过对象存储保存；
- API 集成短信、邮件、电子签、支付和大模型服务；
- 前端静态站与 API 在生产环境中作为两个独立服务构建；Replit 根据两个 artifact 声明的路径进行应用路由。

```text
浏览器
  │
  ├── /、静态资源 ───────────────▶ React + Vite SPA
  │
  └── /api/* ───────────────────▶ Express API
                                      │
             ┌────────────────────────┼────────────────────────┐
             │                        │                        │
             ▼                        ▼                        ▼
        PostgreSQL               对象存储                外部服务
      Drizzle / pg          上传、附件、合同       短信/邮件/电子签/
                                                    支付/DeepSeek
```

## 3. 当前技术栈

### 3.1 基础工具链

| 类别 | 当前实现 |
|---|---|
| Monorepo | pnpm workspace |
| 主要语言 | TypeScript 5.9 |
| 运行时 | Node.js；仓库约定为 Node 24，Replit 模块配置仍包含 Node 20 |
| 包管理器 | pnpm，根脚本拒绝 npm/yarn 安装 |
| 代码生成 | OpenAPI + Orval |
| 服务端构建 | esbuild，输出 ESM bundle |
| 前端构建 | Vite 7 / Rollup |
| 辅助脚本 | TypeScript、Shell；Python 仅用于部分文档/数据工具，不属于正式应用构建链路 |

> Node 版本存在配置漂移：`replit.md` 记录 Node 24，`.replit` 当前声明 `nodejs-20`。迁移到其他环境时必须固定一个主版本并执行完整构建验证，不要依赖“本机恰好能运行”。

| Excel | SheetJS `xlsx` |

### 3.3 后端

| 类别 | 当前实现 |
|---|---|
| HTTP 框架 | Express 5 |
| 数据库驱动 | `pg` |
| ORM | Drizzle ORM |
| 日志 | Pino / pino-http |

### 3.4 数据与接口契约

- 数据库：PostgreSQL；
- Schema：`lib/db/src/schema/`；
- 连接池：`pg.Pool`；
- ORM：Drizzle；
- 接口契约：`lib/api-spec/openapi.yaml`；
- 前端生成客户端：`lib/api-client-react/src/generated/`；
- 服务端生成校验：`lib/api-zod/src/generated/`。

修改 OpenAPI 后必须执行：

```bash
pnpm run codegen
```

根构建命令会自动先执行代码生成。

## 5. 前端代码架构

路径：`artifacts/jiedanba/`

```text
artifacts/jiedanba/
├── src/
│   ├── main.tsx                   # 浏览器入口
│   ├── App.tsx                    # 总路由与顶层 Provider
│   ├── pages/                     # 页面级组件
│   │   ├── opc-v2/                # OPC V2 工作台
│   │   └── pub/                   # 发单方页面
│   ├── components/
│   │   ├── ui/                    # Radix/shadcn 基础组件
│   │   ├── layout/                # 公共站点布局
│   │   ├── publisher/             # 发单方布局与业务组件
│   │   ├── admin-v2/              # 管理后台 V2
│   │   ├── agent/                 # AI 对话与表单联动
│   │   ├── compute/               # 算力中心
│   │   └── tools/                 # 工具、插件、智能体市场
│   └── lib/                       # 浏览器端工具和 API 基础配置
├── vite.config.ts                 # Vite、代理、HMR、构建配置
└── dist/public/                   # 生产静态产物
```

### 5.1 路由与页面

- `App.tsx` 是总路由入口；
- 大多数页面使用动态导入；
- 首页保持同步加载以缩短首屏时间；
- 管理后台、OPC、发单方、社区、大赛、算力和工具平台共用一个 SPA；
- 生产静态服务必须支持 SPA fallback：未知前端路径返回 `index.html`。

### 5.2 API 调用

- 优先使用 `@workspace/api-client-react` 生成的 hooks；
- 同源部署时使用相对路径 `/api/...`；
- 开发环境由 Vite 将 `/api` 代理到 API 服务；
- 不应在浏览器代码中硬编码 localhost、Replit 开发域名或数据库地址。

### 5.3 开发环境代理

在当前 Replit artifact 配置中，Vite 端口为 `24926`；Vite 本身从 `PORT` 读取端口，并不固定为 24926。API 代理目标：

1. 优先读取 `API_PROXY_TARGET`；
2. 未配置时使用 `http://localhost:3000`。

当前 Replit 根工作流把 API 显式运行在 3000，因此浏览器预览链路是：

```text
浏览器预览 → Vite:24926 → /api 代理 → API:3000
```

### 6.1 启动顺序

API 的主要启动过程：

1. 创建 Express app；
2. 监听 `PORT`，默认 8080；
3. 生产环境下检查电子签配置并在缺失时告警；
4. 执行运行期迁移；
5. 执行种子数据逻辑；
6. 启动业务周期任务和算力调度器。

健康检查：

```text
GET /api/healthz
```

> 当前进程先监听，再执行初始化；部分初始化失败只记录日志而不会终止服务。因此“健康检查返回 200”不等于数据库迁移、电子签或后台任务全部可用，发布后还要检查启动日志和关键业务 smoke test。

### 6.2 路由范围

API 统一挂载在 `/api`，主要包括：

- 登录、注册、密码、短信验证码；
- 用户、OPC 档案、作品集；
- 需求、投标、订单、交付、通知；
- 社区、培训、大赛与赛道认证；
- V2 甲方需求、外包需求、投标、订单、合同、支付、结算、交付和工单；
- 管理后台和 RBAC；
- 文件上传、下载和预览；
- AI 智能体；
- 算力中心；
- 工具、插件和智能体市场；
- 支付回调、电子签 webhook。

## 7. 数据库架构与迁移

### 7.1 数据库访问

数据库包：`lib/db/`

- `DATABASE_URL`：应用数据库连接；
- `pg.Pool`：连接池；
- Drizzle：类型安全查询和表结构定义；
- `lib/db/src/schema/`：业务表 Schema；
- `lib/db/drizzle.config.ts`：Drizzle 配置。

业务域包含用户、OPC 档案、赛道认证、需求、投标、订单、交付、合同、支付、结算、工单、社区、课程、大赛、智能体、算力和工具市场等。

### 7.2 当前迁移机制

当前存在两条数据库结构处理路径：

1. API 生产构建的 `build:prod` 会在构建后运行 `scripts/migrate.mjs`，它调用 Drizzle `push-force`；
2. API 启动后还会执行 `src/lib/migrations.ts` 中的幂等迁移和 seed。

当前生产构建命令：

```bash
pnpm --filter @workspace/api-server run build:prod
```

注意：

- `push-force` 是 Schema push，不是版本化迁移文件；“只做增量”目前是脚本约定，并非工具强制保证；
- `DATABASE_URL` 缺失时构建脚本会跳过 push，执行失败时也可能只输出警告；
- 正式发布流水线应在数据库 URL 缺失或结构更新失败时失败关闭，并人工审阅结构差异；
- 任何生产迁移前必须先备份；
- 不要把开发数据库 URL 误用为生产数据库 URL；
- 不要在多个 API 副本上并发执行未加锁的一次性迁移；
- 迁移失败不能只看进程是否还活着，必须检查日志；
- 下载后自建部署时，应把迁移作为独立发布步骤，而不是让每个实例同时启动迁移。

## 8. 认证、权限与安全边界

### 8.1 身份认证

- Bearer JWT 作为访问令牌，通过 `Authorization` 请求头传递；
- bcryptjs 保存密码哈希；
- API 中间件负责认证；
- 前端路由守卫只改善用户体验，不能替代后端授权。

### 8.2 角色

主要角色：

- OPC；
- 发单方；
- 管理员；
- 超级管理员。

管理后台使用 RBAC：

- 管理员角色表保存权限集合；
- 用户与管理员角色通过分配表关联；
- 超级管理员可绕过普通权限列表；
- 所有管理接口仍必须在后端校验权限。

### 8.3 HTTP 安全

服务端使用：

- Helmet；
- CORS allowlist；
- 请求体大小限制；
- API 限流；
- 统一 404 和错误处理；
- Pino 结构化请求日志。

生产环境不要在日志中记录密码、JWT、API Key、支付密钥、身份证件、银行卡号或完整请求体。

## 9. 文件与对象存储

### 9.1 当前机制

浏览器不直接持有云存储密钥。标准上传流程：

1. 前端向 API 请求上传地址；
2. API 生成受限的签名上传 URL；
3. 浏览器直传到隔离位置；
4. API 校验上传 token、文件类型和权限；
5. 业务记录保存对象路径；
6. 下载时由 API 鉴权或生成时效 URL。

Replit 当前通过以下运行配置接入对象存储：

- `PRIVATE_OBJECT_DIR`；
- `PUBLIC_OBJECT_SEARCH_PATHS`；
- `.replit` 中的 Object Storage bucket 配置。

### 9.2 下载后部署的替代要求

Replit Object Storage 的目录和桶不能直接在其他服务器复用。外部部署必须：

1. 选择 S3、GCS、兼容 S3 的对象存储或自建存储；
2. 配置服务端凭据；
3. 配置 bucket、CORS 和签名 URL；
4. 迁移原有对象；
5. 保持数据库中的对象路径与新存储映射一致；
6. 验证上传、下载、Markdown 附件、合同、交付物和 PDF 预览。

数据库备份不包含对象存储文件，二者必须分别备份。

## 12. Replit 开发与发布

### 12.1 当前开发工作流

核心工作流：

| 工作流 | 命令 | 端口 |
|---|---|---:|
| API Server | `PORT=3000 ... pnpm --filter @workspace/api-server run dev` | 3000 |
| 接单吧 Web | `pnpm --filter @workspace/jiedanba run dev` | 24926 |
| 数据库每日备份 | `pnpm --filter @workspace/scripts exec tsx ./src/backup-scheduler.ts` | 无 |

此外还有 artifact API 服务端口 8080。开发预览实际通过 Vite 的 `/api` 代理访问 3000；修改 API 后如果只重启 8080 的服务，浏览器可能仍在使用旧的 3000 进程。

### 12.2 Replit 生产构建

API：

```text
pnpm --filter @workspace/api-server run build:prod
```

运行：

```text
node --enable-source-maps artifacts/api-server/dist/index.mjs
```

环境：

```text
PORT=8080
NODE_ENV=production
```

## 13. 下载源码后的自建部署

### 13.1 最低运行条件

- 64 位 Linux；
- Node.js 20/24 中选定并固定一个经过验证的主版本；
- pnpm；

### 13.2 推荐拓扑

```text

   │

   └── /* ──────▶ Web 静态目录

API
   ├── PostgreSQL
   ├── Object Storage
   └── External APIs
```

前端和 API 推荐同域部署，减少跨域鉴权和 CORS 配置复杂度。

5. 在隔离环境先演练迁移。

#### 步骤 3：配置环境变量

- 使用 systemd EnvironmentFile、云 Secret Manager 或其他密钥管理；
- 不提交 `.env`；
- 不把服务端密钥暴露为 Vite 前端变量；
- 校验域名、CORS、Bearer JWT、支付和电子签回调地址。

#### 步骤 4：替换对象存储

完成第 9 节所述的存储适配和历史对象迁移。

#### 步骤 5：生成代码并检查

```bash

```

#### 步骤 6：构建 API

```bash
NODE_ENV=production \
  pnpm --filter @workspace/api-server run build:prod
```

确认迁移成功后再继续。

#### 步骤 7：构建前端

```bash

  pnpm --filter @workspace/jiedanba run build
```

#### 步骤 8：运行 API


## 14. 后台调度任务

API 启动后会启动多项周期任务，包括：

- 定向需求超时转公开；
- 长时间未处理的交付自动验收；
- 在线退款状态轮询；
- V2 质保期结束自动完成；
- 工具订阅到期和提醒；
- 算力任务调度。

### 14.1 多实例风险

当前周期任务没有统一的 leader election。若部署多个 API 实例：

- 每个实例都可能启动同一任务；
- 外部通知、退款轮询或状态变更可能重复执行；
- 依赖数据库幂等不等于所有外部调用天然安全。

自建多副本部署应选择一种方案：

1. API 多副本，但只有一个实例启用 scheduler；
2. 把 scheduler 拆成单独 worker；
3. 为每个任务增加 PostgreSQL advisory lock 或可靠分布式锁。

## 15. 数据库备份与恢复

### 15.1 当前脚本

备份调度器默认每天本地时间 03:00 执行：

```text
scripts/src/backup-scheduler.ts
```

实际备份：

```text
scripts/backup-db.sh
```

主要变量：

- `PROD_DATABASE_URL`；
- `BACKUP_DIR`，默认 `backups`；
- `RETENTION_DAYS`，默认 30。

脚本使用 `pg_dump | gzip` 生成备份。

### 15.2 当前限制

默认方案只写本地文件，不能单独视为生产灾备：

- 容器或实例销毁时本地文件可能一起丢失；
- 没有自动异地复制；
- 没有备份加密证明；
- 没有自动恢复演练；
- 数据库备份不包含对象存储文件。

### 15.3 生产建议

最低要求：

1. 数据库备份写入独立持久化存储；
2. 再复制到不同故障域；
3. 对象存储单独备份或启用版本保留；
4. 对备份失败、文件大小异常和过期清理失败告警；
5. 每季度恢复到隔离数据库；
6. 抽查用户、订单、合同、支付、结算和附件引用；
7. 记录实际 RPO 和 RTO。

恢复时禁止直接覆盖仍在运行的生产库。先恢复到隔离实例，验证完成后再制定切换方案。

## 19. 常见故障排查

### 19.1 开发预览一直加载

1. 确认 Vite 24926 在监听；
2. 确认 API 3000 在监听；
3. 检查 Vite `/api` 代理目标；
4. 检查浏览器 console 和 Vite HMR；
5. 检查是否存在占用原端口的孤儿进程；
6. 不要给 React lazy 动态导入增加固定超时自动刷新；
7. 普通 TSX/CSS 修改优先 HMR，不要频繁重启前端。

### 19.2 API 修改后前端仍是旧行为

开发预览走 3000。确认重启的是根 `API Server`，不能只重启 artifact 的 8080 API。

### 19.3 发布失败但没有构建日志

1. 本地分别执行前端和 API 生产构建；
2. 如果都通过且发布记录 0 行日志，可能是发布流程在构建前失败；
3. 重试发布；
4. 新构建产生具体日志后再按日志修复；
5. 不要在无日志证据时随意修改应用代码。

### 19.4 前端白屏

- 检查 `BASE_PATH`；
- 检查 SPA rewrite；
- 检查 Vite host/HMR；
- 检查动态导入和浏览器 console；
- 检查生产静态目录是否正确；
- 检查 JSX 中是否使用构建器不支持的泛型实参语法。

### 19.5 附件下载失败

- 检查数据库对象路径；
- 检查 bucket 和权限；
- 检查签名 URL 是否过期；
- 检查迁移时是否只迁了数据库而未迁对象；
- 中文文件名使用 RFC 兼容的 `Content-Disposition`。

## 20. 当前已知技术债与风险

1. Node 20/24 配置存在漂移；
2. API 的开发脚本不是增量 watch；
3. API 监听早于初始化完成，健康检查不能覆盖全部依赖；
4. 迁移失败可能只记录警告；
5. 周期任务在多 API 实例下存在重复执行风险；
6. 默认数据库备份只保存在本地，不构成完整灾备；
7. Replit Object Storage 不能直接移植到外部服务器；
8. 管理后台主页面体积较大，影响开发转换和生产 chunk；
9. `replit.md` 中部分早期 Demo 限制和表数量描述已经过时，应以当前代码和 Schema 为准；
10. 外部部署没有仓库内现成的 Dockerfile、Compose、Nginx 或 systemd 配置，需要按本文拓扑补齐。
